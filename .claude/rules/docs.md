# 产品与技术文档维护规范

## 文档角色与真相源

- **现行基准文档**：
  - `docs/prd/2026-10-25-graph.md`：描述当前已上线/已落地的产品语义（合集、点、边、8 种卡片、交互与界面）。
  - `docs/tech/2026-10-25-graph.md`：描述与现行代码完全一致的系统拓扑、目录职责、数据表、HTTP 接口与前端实现。
- **待落地增量文档**：
  - 在对应代码落地前，代表下一步的目标规格；描述现状仍以现行基准文档为准。
  - 当增量需求开发完成时，必须将增量文档合并进 `docs/prd/2026-10-25-graph.md` 被替换的小节，并同步更新 `docs/tech/2026-10-25-graph.md`。

## 编写与变更原则

- **先文档后代码**：修改产品语义或核心接口契约时，先更新 PRD 与技术文档，再修改代码，确保文档与代码始终零偏差。
- **克制直接**：行文保持短句、直接、无废话；明确区分「现行能力」与「当前不做 / 这一步不做」。
- **禁止回退历史废弃设计**：不得将已删除的旧版文档（扇形布局、领域划分、点类型、能力/证据/FSRS 复习、一跳星图等）重新写回现行文档。
