状态：与合集画板落地后的实现一致。实现以本文为准。

日期：2026-10-25。
产品语义：`docs/prd/2026-10-25-graph.md`。
读者：执行开发的 Agent 或工程师。

不从 Inwit 仓库引用包。富文本的节点和工具对齐 Inwit 文稿编辑器的写作部分（`apps/web/src/pages/docs/paper-toolbar.tsx` 与 `packages/doc-engine/src/vendor/extensions.ts`），在本仓库里重写一版。不搬批注、卡片锚点、Vital 实体、分页、文内查找和视频。

富文本的结构放在 `packages/dto` 和 `apps/web`。仓库里已移除粘贴夹具 `/paste-bench` 以及 `@unfold/doc-schema`、`@unfold/markdown`、`@unfold/search`。

## 1. 拓扑

多用户桌面 Web。一个服务端进程。产品请求不经过 Meilisearch、Qdrant、DashScope，也没有独立 worker。

```
浏览器 SPA (Vite 6 / React 19, http://localhost:5173)
   │ 同源 /api ，开发期 Vite 代理到 127.0.0.1:3000
   ▼
Fastify 5 (apps/server, 127.0.0.1:3000)
   ├── PostgreSQL   DATABASE_URL（Drizzle + pg）
   ├── 图片文件     ASSET_DIR（未设置时用 apps/server/data/assets）
   └── 头像对象     ATTACHMENT_S3_*（私有桶，接口现签临时地址）
```

Vite 开发服务器监听 `[::1]:5173`。用 `localhost` 访问。`/health` 不需要登录。

桌面壳（`apps/desktop`，Tauri 2）开发时打开 `http://localhost:5173`，发布构建打开 `https://unfold.aimo.plus`。地址保持 `localhost`，不要改成 `127.0.0.1`。页面、Cookie 和 `/api` 与浏览器是同一条同源路径。壳不嵌入 `apps/web/dist`，也不保存令牌。见第 10 节。

上面是开发时的进程。部署镜像见第 9 节：同一个 Fastify 进程听 `0.0.0.0:3000`，直接返回页面。

全貌页 `/library` 仍自动排布。合集页 `/c/:id` 的位置按合集记，由客户端写入。服务端不跑布局。

产品页的状态在 `@rabjs/react` 的 `SessionService`、`LibraryService` 和 `SaveService`。图是自定义 SVG。自动排布在 `apps/web/src/features/board/board-layout.ts`，画布是 `GraphViewport`。不用 React Flow。

保存走 `shared/save/`。名字、描述、关系、行内输入和九种卡片把未提交的草稿登记在总线上。停下输入 2 秒后，提交仍开着的草稿；图上那一行创建、改名、改标签不参加，仍等失焦、Enter 或 ⌘S。⌘S 提交全部脏草稿，和失焦同一条写入。失败的那一次不自动重试。`LibraryService` 里会改已有内容的方法（改名、描述、关系、卡片、位置、新建点和边）包一层写入计数。有请求时顶部是保存中；这一轮全部成功是保存成功；有失败是保存失败，说明用原来的错误文案；本地还有改动且没有请求时是未保存。回声回来时，若本地已经又改过，不覆盖。关上页面前若停在未保存、保存中或保存失败，先再交一次草稿，并让浏览器询问。

同一账号的另一处写入成功后，服务端用 WebSocket `GET /api/live` 通知其它页。消息是 `{ client }`，`client` 是请求头 `x-unfold-client`。发出这一次写入的页面自己不处理。收到后只重新读取当前全貌、当前合集图，以及正开着的点、边或合集边，不清空检查器，失败也不改页面上的错误。本地若正有写入，这一次读取作废。内容相同则不替换。通知只留在当前进程的内存里。页面可见时，大约每 5 秒再读一次，用来补上没接到的通知。后一次写入覆盖前一次。正在写的文本仍按上面的回声规则留在本地。

Tiptap 3.31.3 由根 `package.json` 的 overrides 锁定。笔记卡用它存 HTML。富文本卡用它存 `doc`。公式沿用页面上已有的 KaTeX，不用 MathML。Mermaid 沿用 `apps/web` 已有依赖。代码卡片用 CodeMirror 6 编辑，并按语言高亮。富文本里的代码块另用 `lowlight` 的 common 包，配 `@tiptap/extension-code-block-lowlight`。公式节点用 `@tiptap/extension-mathematics`。界面图标用 `lucide-react`。

web 和 server 的运行时依赖没有 `@unfold/doc-schema`、`@unfold/search`、`@unfold/markdown`、`ts-fsrs`。不从 Inwit 仓库引用包。对象存储用 `@aws-sdk/client-s3` 和 `@aws-sdk/s3-request-presigner`，预签名在本地完成，不发请求。

点的名字只做 trim，允许重名。`packages/dto` 已移除 `normalizeName`。

密钥只在 `apps/server/.env`。文档和代码里只出现变量名。

| 变量 | 谁读取 |
| --- | --- |
| `DATABASE_URL` | 服务端、迁移、种子 |
| `SESSION_SECRET` | Cookie 签名 |
| `UNFOLD_ENV` | `production` 时登录 Cookie 加 `Secure`，并托管 `apps/web/dist` |
| `HOST` | 监听地址。未设置时是 `127.0.0.1`。镜像里是 `0.0.0.0` |
| `PORT` | 监听端口。未设置时是 `3000` |
| `SEED_USERNAME` | `pnpm --filter @unfold/server seed`，以及服务端集成测试 |
| `SEED_PASSWORD` | 同上。不要写进文档、日志或提交 |
| `ASSET_DIR` | 图片文件目录。未设置时用 `apps/server/data/assets` |
| `ATTACHMENT_S3_BUCKET` | 头像对象存储桶 |
| `ATTACHMENT_S3_ACCESS_KEY_ID` | 对象存储访问密钥 id |
| `ATTACHMENT_S3_SECRET_ACCESS_KEY` | 对象存储访问密钥 |
| `ATTACHMENT_S3_REGION` | 对象存储区域 |
| `ATTACHMENT_S3_ENDPOINT` | 自建或兼容 S3 的入口。可以不设 |
| `ATTACHMENT_S3_IS_PUBLIC` | `true` 时头像用公开地址，不签名 |
| `ATTACHMENT_S3_FORCE_PATH_STYLE` | `true` 时用 path-style 寻址 |

服务端启动只要求前三项和 S3 的桶、密钥、区域。`ASSET_DIR`、`ATTACHMENT_S3_ENDPOINT` 可以不设。`loadConfig()` 不读取检索或模型相关变量。

把 `apps/server/data/assets` 写进 `.gitignore`。键是资产 id，不使用用户提供的文件名。

迁移：`pnpm --filter @unfold/server migrate`。Drizzle 按 `apps/server/drizzle/meta/_journal.json` 执行 SQL。`0000` 到 `0008` 是重构前的表，新库仍会先执行它们。`0009_graph_core.sql` 删掉这些业务表（保留 `users`），再创建现在的图。`0010_node_description.sql` 给 `nodes` 加 `description`。`0011_canvas.sql` 给 `nodes` 加 `kind`，给 `memberships` 加 `x`、`y`、`z`、`image_width`，新建 `assets`，并允许 `cards.card_type` 为 `rich`。已有行都是文字点，位置先空着。`0012_user_avatar.sql` 给 `users` 加 `avatar_key`。`0013_edge_label_required.sql` 要求边的标签非空。`0014_canvas_settings.sql` 给 `collections` 加连线外观，给 `users` 加画布看法。`0015_collection_inclusions.sql` 新建 `collection_inclusions`，记下子集合放在哪个合集上。`0016_canvas_grow.sql` 给 `users` 加 `canvas_grow`，默认 `down`。已迁移过的库只会再跑尚未记录的文件。迁移可以连续执行两次。

注册和种子用户都用 argon2（argon2id）。注册开放，限流与登录相同。

## 4. 表

业务行都带 `user_id`，`collection_inclusions` 除外：它通过两端合集校验归属。主键是 UUID，`gen_random_uuid()`。除成员关系和子集合放入外，删除写 `deleted_at`。另一位用户的 id 查不到，返回 404。

| 表 | 字段 | 约束 |
| --- | --- | --- |
| `users` | `username`，`password_hash`，`avatar_key`，`canvas_route`，`canvas_grid`，`canvas_snap`，`canvas_labels`，`canvas_markers`，`canvas_minimap`，`canvas_grow` | `username` 唯一。`avatar_key` 可空，是头像在对象存储里的键。画布看法默认直线、点阵开、吸附关、标签始终、卡片标记开、小地图开、下级方向向下。`canvas_route` 为 `straight` / `curve` / `orthogonal`。`canvas_labels` 为 `always` / `focus`。`canvas_grow` 为 `up` / `down` / `left` / `right` |
| `collections` | `title`，`edge_dash`，`edge_width`，`edge_color`，`edge_arrow` | 无名称唯一约束。连线外观默认细灰实线、终点有箭头。线型 `solid` / `dashed` / `dotted`，粗细 `thin` / `medium` / `thick`，颜色 `gray` / `blue` / `green` / `red`，箭头 `end` / `none` |
| `nodes` | `name`，`description`，`kind` | 无名称唯一约束。描述 trim 后不超过 160 字。`kind` 为 `text` 或 `image`，默认 `text`。图片点的脸是 `image`，不是第五个名词，也不是一种卡片 |
| `memberships` | `collection_id`，`node_id`，`x`，`y`，`z`，`image_width` | 联合主键是合集和点。删除是物理删除。位置按合集记，不记在点上。`x`、`y`、`z`、`image_width` 可空。`image_width` 只对图片点有意义，有值时在 120 到 480 |
| `collection_inclusions` | `parent_id`，`child_id`，`x`，`y`，`collapsed` | 联合主键是父合集和子集合。禁止自己放自己。删除是物理删除。`x`、`y` 是锚点：子集合里点的世界坐标等于它自己的坐标加上锚点。`collapsed` 默认 false |
| `edges` | `from_id`，`to_id`，`label` | 禁止自环；标签 trim 后非空；未删除行上 `(user_id, from_id, to_id, label)` 唯一 |
| `collection_edges` | 同上，两端是合集 | 同上 |
| `cards` | `owner_kind`，`owner_id`，`card_type`，`position`，`content jsonb` | `owner_kind ∈ node/edge/collection_edge`。`card_type` 为原来的八种加 `rich`。原来八种的 `content` 键由类型决定，值都是字符串。`rich` 只允许 `owner_kind = node` |
| `assets` | `id`，`user_id`，`owner_kind`，`owner_id`，`mime`，`byte_size`，`created_at` | 新表。文件不进数据库，放在 `ASSET_DIR` |

`assets.owner_kind` 为 `node` 或 `card`。`owner_kind = node` 时，这个点同时最多一行；换图先删旧行和旧文件。`owner_kind = card` 时，只属于 `card_type = rich` 的卡。

图片资产的 `mime` 只允许 `image/jpeg`、`image/png`、`image/webp`、`image/gif`，单张不超过 10 MiB。不合规则不创建资产，也不创建图片点。文案与产品文档相同：「只能放入 JPEG、PNG、WebP 或 GIF」，「图片不能超过 10 MB」。

`rich` 的 `content` 是：

```json
{ "doc": { "type": "doc", "content": [ { "type": "paragraph" } ] }, "plain": "" }
```

`plain` 由服务端根据 `doc` 生成，客户端传上来的 `plain` 不采用。生成时按文档顺序拼接：普通文本、代码块文本、公式的 LaTeX、Mermaid 源码、图片的替代文本。块与块之间换行。

`doc` 序列化后的 UTF-8 不超过 1 MiB。超过则这次保存返回 400，文案「这篇文稿太大了」，不改旧内容。

点与合集之间没有边。删除合集时，软删它参与的合集边和这些边上的卡片，并物理删除它的成员关系，以及它作为父合集或子集合的放入关系。不删除点，不删除另一头的合集，也不删点的资产。删除点时，软删它的卡片、它参与的点边和这些边上的卡片，物理删除它的成员关系，并删掉它的脸部资产、这些卡片名下的资产和文件。删除一条边时，软删挂在它上面的卡片。删除富文本卡时，删掉它名下的资产和文件。移出合集只删 `memberships` 那一行，不动点和资产。移出子集合只删 `collection_inclusions` 那一行，不删合集，也不删合集边或点边。

读出资产时带 `X-Content-Type-Options: nosniff`，按 `mime` 内联返回。

头像不进 `assets` 表，也不进 `ASSET_DIR`。头像对象在 S3 桶里，键是 `avatars/<userId>/<uuid>.<ext>`，`users.avatar_key` 记当前键。格式与图片资产相同，单张不超过 5 MiB，文案「头像只能是 JPEG、PNG、WebP 或 GIF」「头像不能超过 5 MB」。换头像先上传新对象、再改 `avatar_key`、最后删旧对象。桶私有：每次 `GET /api/me` 和登录、注册、换头像的响应都现签一个 GET 临时地址（1 小时），客户端直接用；过期后重新调 `/api/me` 取新地址。`ATTACHMENT_S3_IS_PUBLIC=true` 时不签名，直接拼公开地址。

## 5. HTTP

Cookie 名 `unfold_session`，签名，HttpOnly，SameSite=Lax，`Max-Age` 为 400 天（34560000 秒）。登录和注册时写下，退出时清掉。没有过期时间时，WebView 把它当成会话 Cookie，进程退出就丢掉，桌面客户端每次重新打开都要登录。400 天是 Chromium 对 Cookie 有效期的上限。错误体是 `{ "error": { "code", "message" } }`。未登录是 401 `unauthenticated`。请求体不合法是 400 `invalid_body`。登录失败是 401 `invalid_credentials`。登录每分钟最多 30 次，超出是 429 `rate_limited`。

创建返回 201。读取和更新返回 200。删除、加入成员、移出成员、保存位置返回 204。重复加入同一个成员也返回 204。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/register` | `{ username, password }` → 201 `{ username, avatarUrl, canvas }`，同时种下会话 Cookie。用户名已占用返回 409 `conflict`，文案「这个用户名已经被用了」 |
| POST | `/api/login` | `{ username, password }` → `{ username, avatarUrl, canvas }` |
| POST | `/api/logout` | 清 Cookie |
| GET | `/api/live` | WebSocket。查询 `client` 为 uuid。未登录直接关掉。其它页写入成功时收到 `{ client }`。登录、退出、注册和 `/api/me` 不发。通知不跨进程 |
| GET | `/api/me` | `{ username, avatarUrl, canvas }`。`avatarUrl` 每次现签；没有头像时为 `null`。`canvas` 是账号上的画布看法 |
| PATCH | `/api/me/username` | `{ username }` → `{ username, avatarUrl, canvas }`。占用返回 409 `conflict`，文案同上 |
| PATCH | `/api/me/canvas` | 整份 `{ route, grid, snap, labels, markers, minimap, grow }` → 同一份。`grow` 为 `up` / `down` / `left` / `right`，默认 `down`。不发实时通知。非法枚举返回 400 `invalid_body` |
| PUT | `/api/me/avatar` | `multipart` 字段 `file` → `{ avatarUrl }` |
| DELETE | `/api/me/avatar` | 移除头像，返回 204 |
| GET | `/health` | `{ ok: true }` |
| POST | `/api/collections` | `{ title }` |
| GET | `/api/collections` | `{ collections }`，每条带 `nodeCount` |
| PATCH | `/api/collections/:id` | `{ title }` |
| DELETE | `/api/collections/:id` | |
| GET | `/api/library` | 全部合集（带 `nodeCount`）和合集边（带 `cardCount`） |
| GET | `/api/collections/:id/graph` | 成员点带 `cardCount`、`cardTypes`、`kind`、`x`、`y`、`z`、`imageWidth`、`assetId`。两端都是成员的点边带 `cardCount`。未摆放过的 `x`、`y` 为 `null`。没有脸时 `assetId` 为 `null`。另带 `appearance`。`inclusions` 是放进来的子集合，每条有 `childId`、`title`、锚点 `x`/`y`、`collapsed`、合集边 `labels`，以及该子集合自己的 `nodes` 和内部 `edges`。`bridges` 是跨父合集与子集合、或跨两个子集合的点边。空合集也返回外观和空的 `inclusions`。不返回文稿正文，不嵌资产字节。子集合内部再放入的合集不展开 |
| PATCH | `/api/collections/:id/appearance` | 整份连线外观 → 同一份。不写在边上。合集不存在返回 404 `not_found`。这条会走实时通知。不改 `PATCH /api/collections/:id`，那条仍然只收标题 |
| PATCH | `/api/collections/:id/placements` | `{ placements: [{ nodeId, x, y, z, imageWidth? }] }`。只接受本合集的成员。`x`、`y` 是有限数。`z` 是整数。文字点忽略 `imageWidth`。图片点的 `imageWidth` 缺省则不改，给出则夹到 120–480。返回 204 |
| POST | `/api/collections/:id/nodes` | `{ name }`，创建文字点并加入该合集。位置随后用 placements 写入 |
| POST | `/api/collections/:id/images` | `multipart` 字段 `file`，可选 `x`、`y`。创建图片点和成员。名字按产品文档从文件名得到。返回 201 的点 |
| POST | `/api/collections/:id/members` | `{ nodeId }` |
| DELETE | `/api/collections/:id/members/:nodeId` | 移出，不删点，不动资产 |
| GET | `/api/collections/:id/inclusion-candidates` | 可以放入的合集。每条有 `id`、`title`、`nodeCount`、`linked`、`labels`。不含自己、已经放入的、以及会绕回去的 |
| POST | `/api/collections/:id/inclusions` | `{ childId, originX, originY, label? }`。`originX`、`originY` 是边框左上角，服务端按子集合已摆放点的最小坐标换成锚点。没有合集边、也没有跨集合点边时，`label` 必填，并写成从当前合集指向子集合的合集边。缺标签返回 400 `invalid_body`，文案「要先写下两者的关系」。放进自己返回 400，文案「不能把合集放进自己」。绕回去返回 400，文案「这样放会绕回自己」。已经放入返回 409 `conflict`，文案「这个合集已经在里面了」。成功 201 `{ childId }`，默认展开 |
| PATCH | `/api/collections/:id/inclusions/:childId` | `{ x?, y?, collapsed? }`。这里的 `x`、`y` 是锚点。至少一项。不在里面返回 404 `not_found`，文案「这个合集不在里面」。返回 204 |
| DELETE | `/api/collections/:id/inclusions/:childId` | 移出子集合。返回 204。不在里面同样 404 |
| GET | `/api/nodes/:id` | 点、所在合集、点上的卡片 |
| PATCH | `/api/nodes/:id` | `{ name? }` 或 `{ description? }`，至少给一个 |
| PUT | `/api/nodes/:id/image` | `multipart` 字段 `file`。点必须已是图片点，否则 400，文案「这是文字点」。成功前旧图仍可读 |
| DELETE | `/api/nodes/:id` | 同时删脸部资产、卡片和卡片名下的文件 |
| GET | `/api/assets/:id` | 需登录。不是本人的返回 404。脸部地址是 `/api/assets/` 加上 `assetId` |
| POST | `/api/edges` | `{ fromId, toId, label }` |
| GET | `/api/edges/:id` | 含两端名字和卡片 |
| PATCH | `/api/edges/:id` | `{ label }` |
| DELETE | `/api/edges/:id` | |
| POST | `/api/collection-edges` | `{ fromId, toId, label }` |
| GET | `/api/collection-edges/:id` | 含两端标题和卡片 |
| PATCH | `/api/collection-edges/:id` | `{ label }` |
| DELETE | `/api/collection-edges/:id` | |
| POST | `/api/cards` | `{ ownerKind, ownerId, type, content }`。`type: "rich"` 时 `ownerKind` 必须是 `node`，否则 400，文案「富文本只挂在点上」。`rich` 的 `content` 只收 `{ doc }` |
| PATCH | `/api/cards/:id` | `{ content }`。按已存类型校验，不能改类型。`rich` 按 `doc` 校验，并重写 `plain`。保存成功后，这张卡名下不再被 `doc` 引用的资产和文件删掉 |
| POST | `/api/cards/:id/assets` | `multipart` 字段 `file`。卡必须是本人的 `rich`，否则 404。返回 201 `{ id }` |
| DELETE | `/api/cards/:id` | 删富文本卡时，删掉它名下的资产和文件 |
| GET | `/api/search?q=` | `{ hits }`，最多 30 条 |

自环返回 400，文案「不能连到自己」。重复的活动边返回 409 `conflict`，文案「这条关系已经有了」。找不到时的 `code` 是 `not_found`。

契约在 `packages/dto/src/graph.ts`。`cardSchema` 按 `type` 区分成联合。原来八种的 `content` 仍是 `z.strictObject` 的字符串字段。`rich` 的 `content` 是 `{ doc, plain }`。响应里的卡片字段名是 `type`，对应表列 `card_type`。`cardTypeSchema` 和 `graphNodeSchema.cardTypes` 包含 `rich`。图节点 schema 加上 `kind`、`x`、`y`、`z`、`imageWidth`、`assetId`。

`doc` 用白名单校验，不执行里面的 HTML。允许的节点：`doc`、`paragraph`、`heading`、`text`、`bulletList`、`orderedList`、`listItem`、`taskList`、`taskItem`、`blockquote`、`codeBlock`、`horizontalRule`、`hardBreak`、`table`、`tableRow`、`tableHeader`、`tableCell`、`image`、`inlineMath`、`blockMath`、`mermaid`。允许的标记：`bold`、`italic`、`strike`、`code`、`link`、`textStyle`、`underline`、`subscript`、`superscript`。

属性只留这些：

- `heading.level`：1 到 6
- 块上的 `textAlign`：`left`、`center`、`right`
- `textStyle`：`color`、`fontSize`、`backgroundColor`。颜色是 `#` 加 6 位十六进制，或空。字号是产品文档那一列，或空
- `link.href`：字符串，最长 2000
- `codeBlock.language`：字符串，最长 40
- `image.src`：本卡资产的 UUID。`alt` 最长 200。`width` 是 32 到 1200 的数，可空
- 单元格：`colspan`、`rowspan` 是 1 到 20 的整数，`backgroundColor` 同上
- `inlineMath` / `blockMath` 的 `latex`：字符串，最长 8000
- `mermaid` 的源码属性：字符串，最长 20000
- `taskItem.checked`：布尔

图片的 `src` 必须是这张卡、这个用户名下的资产。否则 400，文案「文稿里有找不到的图片」。

## 6. 搜索

`GET /api/search` 用 PostgreSQL `ILIKE`。匹配点的 `name`，以及 `owner_kind = 'node'` 的卡片 `content::text`。富文本的正文因此能命中。`%`、`_`、`\` 会转义。空查询返回空列表。不查边上的卡片，也不查合集标题。不识别图片里的字。

每条命中是 `{ nodeId, name, collectionId, collectionTitle, snippet }`。合集取该点所属合集里 `created_at` 最早的一个未删除合集。没有合集时这两个字段是空字符串。摘录优先用点名；点名未命中时，用第一张命中卡片里的字符串拼起来，截到 80 个码位。摘录函数只取字符串字段。`plain` 会进入摘录，`doc` 对象跳过。命中富文本时摘的是 `plain`。

悬停摘录同样只拼接字符串字段。轮到富文本时，用正文开头，不把内部结构摊开。

## 7. 前端

| 路径 | 页面 |
| --- | --- |
| `/` | 恢复会话后去 `/library`，否则去 `/login` |
| `/login` | 登录，页上有去注册的链接 |
| `/register` | 注册，注册成功直接进入 `/library` |
| `/library` | 合集全貌。自动排布，没有画板工具栏，不能上传图片 |

`LibraryPage` 和 `CollectionPage` 共用 `LibraryService`。壳层在两者之间切换，两页不会同时挂载。

`layoutBoard`：没有边，或存在环，或 Kahn 分层放不完所有点时，横排（宽 168，高 56，间距 36，原点 32,48）。无环时从左到右分层，层距 220，纵向间距 28。自环和端点不在图上的边不参与布局。全貌页每次用它排布。合集页只在每个成员的 `x` 都是 `null` 时用它算一次起点，然后写入 placements。文字点宽 168。没有描述时高 56，有描述时画出高 74，描述最多两行，超出隐藏。坐标仍用保存的 `x`、`y`。

位置由客户端计算后写入 `PATCH /api/collections/:id/placements`。服务端不跑布局。

- 打开合集时，若每个成员的 `x` 都是 `null`，用 `layoutBoard` 算一次并保存。已有边的分层、横排规则不变。
- 只有一部分成员的 `x` 是 `null` 时，不重排已有的点。这些新成员落在当前视野中心，左上角互相挡住时向右下错开 24。
- 拖动超过 4px 才记为移动。松手保存 `x`、`y`，并把 `z` 设为当前合集里的最大值加 1。保存失败则回到松手前的坐标。
- `GraphViewport` 的 `resetKey` 改为合集 id。保存位置、新建和改标签都不重新适应屏幕。进入合集时适应一次。

`BoardCanvas`：可选点阵、节点上的描述（最多两行，超出隐藏）、卡片计数徽标和类型色点、边标签旁的卡片数。点阵是视口上的 CSS 圆点，世界间距 16，屏幕上约 1.5 像素，跟着平移和缩放。图片点画出脸，描述不压在图片上。双击空白调 `onBackgroundDoubleClick` 内联创建（只在选择工具下），双击节点内联改名（全貌页是打开合集），悬停点时四边中点各有一个蓝色圆点，从任一圆点拖到另一个节点连线。悬停 450ms 出预览（`LibraryService.loadPeek`，不动 `nodeDetail`），按可见画布放在点旁：右侧放得下就放右侧，否则放左侧，并让开检查器和左侧工具栏。按下并拖动点时不打开预览，同时禁止选中文字。指针离开点和预览后约 280ms 再关预览，这段时间移入预览则保持。预览超出高度可以滚动，滚轮在预览上不平移画布。方向键按空间距离移动选中，Enter 打开或改名，选中边时 Enter 改标签，Esc 先关属性弹层，否则取消选中或取消进行中的操作。选中点、点边或合集边时，Backspace 或 Delete 打开检查器里的删除确认，确认后才删。右键按命中分开：`[data-node-id]` 是点，`[data-edge-id]` 是边，其余空白是画布。菜单项由 `boardMenu` 按合集或全貌拼出，缩放三项留在 `GraphViewport`。删除项只把检查器里的确认打开。预览、缩放条、小地图和行内输入不接这套菜单。焦点在输入框、文本框或富文本里时不拦截。这两个键不删除合集。世界坐标换算用内层 `<g>` 的 `getScreenCTM()`。

`UModal` 挂到 `document.body`。检查器有 `backdrop-filter`，里面的 `position: fixed` 会相对检查器定位，再被 `overflow: hidden` 裁掉。边的检查器宽 340，确认弹层宽 400，留在检查器里时右侧的删除按钮会出界。

边的几何在 `edge-geometry.ts`。直线从两点中心的连线与各自边框的交点相连。曲线用同一对端点，弯出量约为弦长的 0.2，上限 80。折线按水平或垂直进出边框，圆角约 12。同一对端点上的多条边，按稳定次序错开 16；方向相反的边分在两侧。标签在直线或曲线的中点，折线放在较长的一段。合集画布用账号上的 `route`，全貌固定直线。颜色、粗细、线型、箭头来自合集的 `appearance`，画在 `edge-style.ts`。选中时在原线下面加一圈强调色，不改这套颜色。箭头是单独的三角形，尖端在终点边框，线缩短到箭头底部，线帽用平头，避免线和箭头叠色。临时线保持直线虚线。双击标签或线，打开 `InlineInput`，位置用当前走线的标签点。线画在点的下面。

点阵、小地图、标签疏密对全貌和合集都生效。卡片标记关掉时，只藏合集画布上的卡片数和类型色点；全貌的成员点数仍画。吸附在 `snap.ts`，步长 16，只在合集画布生效。拖动、双击、文字工具、Tab、Enter、未摆放的点落在视野中心，都走它。Tab 和右键建下级的位置由账号上的 `grow` 决定，默认 `down`，算在 `planGrow`。左右被挡住向下让，上下被挡住向右让。名字写下之后再连一条边，标签是「下一级」。Enter 建同级不连边，始终放在下方。全部坐标都是空、第一次用 `layoutBoard` 写下的那一次不吸附。图片宽度不吸附。

属性弹层是 `BoardSettings`，由合集工具栏在连线按钮下打开。`LibraryService.updateAppearance` 调 `PATCH /api/collections/:id/appearance`，`SessionService.updateCanvas` 调 `PATCH /api/me/canvas`。两次都先改本地，整份提交，过期响应不覆盖后一次。失败写回原值。外观失败进 `library.error`。看法失败进 `session.canvasError`，不进 `session.error`。这两条都不进 `SaveService`。全貌页只把 `canvas` 传进去，不传外观，也不显示属性。

图片点的盒子宽是 `imageWidth`，缺省 220，高等于宽除以原图比例。选中时右下角拖动，松手把宽度写入 placements，夹到 120–480。

工具栏是合集画布左侧的选择、文字、图片、连线，快捷键 V、T、I、L，下面是「子集合」，再加「属性」。I 打开文件选择，不是停留模式。子集合打开选择弹窗，属性打开设置，两者都不切换工具。拖放和 ⌘V 的落点判断：目标在富文本或任一输入区里时，事件留给那里；否则按产品文档创建图片点。落在展开的子集合边框里时，图片点建在那个子集合里。全貌页继续调用 `BoardCanvas`，不传位置，不显示这套工具栏。

子集合的投影在 `inclusion-view.ts`。展开时，子集合的点用自己的坐标加上锚点，画在父合集的世界坐标里。边框由这些点的盒子加上内边距 28 和标题高 32 算出；没有已摆放的点时，边框是锚点处 280×160。收起时画成一个点，标识是 `inclusion:` 加子集合 id。拖边框把位移加到锚点上。拖边框里的点，写回那个子集合的 `placements`，坐标先减去锚点。`bridges` 在子集合收起时，落在子集合里的那一端改接到这个点上。已经是父合集成员的点不在边框里再画。

笔记卡用 Tiptap（`@tiptap/starter-kit`）做短文，`body` 存 HTML，停下输入约 2 秒、失焦或 ⌘S 保存，搜索摘录在服务端去标签。代码卡用 CodeMirror 编辑，并按语言高亮。新建时 `language` 是 `JavaScript`。语言在卡片顶栏用可搜索的 `USelect` 选择，输入匹配语言名、别名和扩展名。停下输入约 2 秒、失焦或 ⌘S 写入。时段和事件的日期用 `UDateField`（可手输自由文本，也可开日历选 `YYYY-MM-DD`）。

富文本编辑器放在 `apps/web/src/features/cards/rich/`。`card-meta.ts` 加一行：类型 `rich`，标签「富文本」，徽记「稿」。色相用 `#1D4E89`，避开现有八种。

`CardStack` 增加可选的类型列表。点的面板传入九种。边和合集边的面板不传 `rich`，添加按钮里就没有它。富文本只挂在点上。

空卡是 `{ doc: { type: "doc", content: [{ type: "paragraph" }] } }`。工具条的项和产品文档一致，放不下时收到「更多」里，项的顺序不变。按钮是图标，悬停显示该项的名称。字号、对齐和标题用 `USelect`。对齐的按钮和选项只画图标。代码语言不在工具条上，在代码块右上角用可搜索的 `USelect` 选择，输入匹配语言名和别名。新建代码块写入 `javascript`。工具条和 `Mod-Alt-c` 都带上这个语言。表格紧挨代码块，公式紧挨表格，引用在工具条最后。表格条只在光标位于表格时出现，按钮居中，同样是图标加名称。

字色默认一组：赤 `#b3402a`、赭 `#9a6232`、绿 `#2f7d4a`、蓝 `#2a5f9e`、紫 `#6a4c93`、墨 `#221d16`、灰 `#6f675c`。底色默认一组：黄 `#f6e7a8`、绿 `#d7efd4`、蓝 `#d6e6f7`、粉 `#f8d6d0`、紫 `#e7dff6`、灰 `#ece7df`。单元格底色用底色这一组。两组之外接受手填的 `#RRGGBB`。

下划线、上标、下标没有单独按钮。粘贴带进来时保留，清除格式时去掉。

公式用 `@tiptap/extension-mathematics` 的行内和块级节点，渲染用 KaTeX。插入时问一句 LaTeX：含换行或被 `$$` 包住则成块，否则行内。排不出时显示原来的 LaTeX。Mermaid 源码存在节点上，渲染失败时显示源码和「这张图没有画出来」。

链接 `openOnClick: false`，自动识别。工具里改地址；清空则取消链接。打开时新开一页。

粘贴时，剪贴板 HTML 里认得出的格式直接进入文稿：标题、列表、引用、代码、表格、对齐、粗体、斜体、删除线、下划线、上标、下标、行内代码、链接、字色、底色和字号。字号收成工具条里最近的一档。HTML 已经带格式时，不用纯文本或 `text/markdown` 再解析一遍。没有 HTML 格式时，有 `text/markdown` 就用它，否则再看纯文本里的 Markdown，转成对应节点，包含行内的粗体、斜体、删除线、行内代码和链接。HTML 预处理写在 `features/cards/rich/paste-html.ts`，Markdown 解析写在 `paste.ts`，插入写在 `paste-insert.ts`。光标在段落或标题中间时，块级内容从这里拆开插入，周围已有的文字留下。图片文件单独粘贴、或和没有格式的文字一起粘贴时，走 `POST /api/cards/:id/assets`，再把返回的 id 写入 `image.src`。和带格式的文字在同一份剪贴板里时，留下文字，不改成图片。进行中的落点显示占位。失败则去掉占位，文稿其余部分不动。格式和大小与图片点相同。文稿里的图片不是新的图片点。

保存：输入停止 800ms 后提交；失焦再提交一次；⌘S 立刻提交。序列化结果与上次成功保存相同则不请求。同一份快照在回声或失败之前不重复提交。文稿超过 1 MiB 时不覆盖旧内容，提示「这篇文稿太大了」。编辑器自己的撤销栈用 Tiptap history，不写入服务端。画板一级没有撤销。

正文用衬线，代码用等宽，和笔记卡同一套字体令牌。编辑区最小高度 360。工具条在这张卡处于检查器可视范围时粘在检查器内容区顶部。

`.board-panel` 仍是 340。点的面板加修饰类，默认宽 640。左缘 6px 宽的拖条改宽度，限制在 480 到 880，并保证画布剩余至少 320。数值写入 `localStorage` 键 `unfold.node-panel-width`。读到非法值就用 640。边、合集边、全貌页的面板不加这个修饰类，仍宽 340。拖条上的指针事件不冒泡到画布，避免被当成平移。

## 8. 检查

`pnpm test`、`pnpm typecheck`、`pnpm lint`。服务端集成测试通过 `buildApp` 和 `inject` 打到 `DATABASE_URL` 指向的库，使用种子用户。图的集成测试在结束时删除自己创建的点和合集，并删掉对应文件。

服务端集成测试补这些情况：旧点的 `kind` 是 `text` 且位置为空；placements 不改别的合集；图片类型和 10 MiB 边界；`rich` 挂到边上得到 400，文案「富文本只挂在点上」；`doc` 里引用别人的资产得到 400；保存后 `plain` 含公式和代码文本；超过 1 MiB 返回 400，文案「这篇文稿太大了」，旧内容还在；删除点和删除富文本卡都会删掉资产行。

前端为 `layoutBoard` 的旧用例保持通过。另测：已有位置的点不再被自动排布改掉；摘录函数遇到 `{ doc, plain }` 只用 `plain`。

`pnpm --filter @unfold/desktop test` 检查壳的 URL、导航和权限契约。不要求本机安装 Rust。

## 9. 镜像

`.github/workflows/docker-build.yml` 在推送到 `main` 或 `master`、打 `v*.*.*` 标签，或手动触发时构建 `apps/server/Dockerfile`，并推到 `ghcr.io/<owner>/unfold-server`。路径过滤是 `apps/server`、`apps/web`、`packages`、根清单、锁文件和这条 workflow 自身。标签含分支名、语义化版本和提交 SHA。默认分支另有 `latest` 与 `stable`。只构建 `linux/amd64`。这条 workflow 只推镜像，不在机器上拉起容器。

应用机不构建镜像，也不接收源码。生产 compose 使用 `ghcr.io/ximing/unfold-server:stable`。主机、拉取和迁移的步骤写在 `docs/deploy.md`。

镜像里只有 Fastify。它用 `tsx` 跑 `apps/server/src`，听 `HOST`:`PORT`（镜像里是 `0.0.0.0:3000`）。`UNFOLD_ENV=production` 且存在 `apps/web/dist/index.html` 时，同一个进程返回页面。`/library` 与 `/c/:id` 刷新时回到 `index.html`。`/assets/` 长缓存。`/api` 未命中仍是 404 `not_found`。`/health` 仍是接口。开发时 `UNFOLD_ENV` 不是 `production`，不托管页面，监听地址仍是 `127.0.0.1`。

启动时仍要提供第 3 节的环境变量。`UNFOLD_ENV=production` 时登录 Cookie 带 `Secure`，前面需要 HTTPS。图片目录把 `ASSET_DIR` 挂成卷。迁移覆盖命令为 `node --import tsx src/migrate.ts`，工作目录是镜像内的 `apps/server`。

镜像的两个 `pnpm install` 阶段会复制 `apps/desktop/package.json`，只为让锁文件里的 workspace 成员在场。镜像不编译、不运行桌面壳。

## 10. 桌面壳

`apps/desktop` 是 Tauri 2 窗口。`tauri dev` 加载 `build.devUrl` `http://localhost:5173`。`tauri build` 加载 `build.frontendDist` `https://unfold.aimo.plus`。没有 `beforeBuildCommand`，安装包不包含 `apps/web/dist`。页面更新只靠站点发布。

会话是 WebView 自己的 Cookie `unfold_session`（HttpOnly，SameSite=Lax，`Max-Age` 400 天，生产带 Secure）。过期时间让 WebView 在进程退出后仍保留登录。壳和系统浏览器不共享这枚 Cookie。壳不注入 `Authorization`，不使用 `tauri-plugin-http`、`tauri-plugin-store`。Web 源码不检测 Tauri，也不调用 IPC。

`beforeDevCommand` 在 `5173` 还没有页面时，于仓库根启动 `pnpm --filter @unfold/web dev`。它不启动 `apps/server`。登录需要 `3000` 上已有的 API，开发时先跑 `pnpm dev`。

图标来自仓库根目录 `logo.png`。ImageMagick 去掉近白底，画在 1024 画布上：外圈透明，中间圆角白底，标记居中。`tauri icon` 再导出各尺寸。Windows 和 Linux 的菜单栏托盘用标记的黑色模板。macOS 菜单栏没有这枚图标。

窗口 1280×800，最小 960×640，系统标题栏。`create: false`，在 `setup` 里用 `WebviewWindowBuilder` 挂上导航钩子。`on_navigation` 拒绝 `tauri:` 和 `tauri.localhost`，放行 `http:`、`https:` 和 `about:`。`window.open` 只在 `on_new_window` 里交给系统浏览器，并拒绝新的 WebView。菜单「重新加载」在当前源是应用源时刷新；离开应用源时回到 `devUrl`（仅 `cfg(dev)`）或 `frontendDist`。macOS 红灯隐藏窗口，从 Dock 再打开。标识符 `plus.aimo.unfold`。

capability 只有 `"local": true`，权限数组为空。不写 `remote`。`withGlobalTauri` 为 false，`csp` 为 null。窗口几何由 `tauri-plugin-window-state` 在进程内恢复，并排除 `VISIBLE`，避免把隐藏记成下次不显示。页面没有这些插件的 JS 权限。

`.github/workflows/desktop-release.yml` 在推送标签 `desktop-v*` 或手动触发时构建安装包，并上传到同名 GitHub Release。四条矩阵：`windows-latest`（Windows x64）、`ubuntu-22.04`（Linux x64）、`macos-latest`（Apple 芯片，`aarch64-apple-darwin`）、`macos-15-intel`（Intel，`x86_64-apple-darwin`）。版本取 `tauri.conf.json`，须与 `Cargo.toml` 和 `apps/desktop/package.json` 相同。标签名是 `desktop-v` 加上这个版本。没有 `beforeBuildCommand`，不编译 `apps/web`。这条 workflow 不构建、不发布服务端镜像。
