# Unfold PRD v2：扇形探索的知识体系与深度学习系统

状态：待确认。确认这份 PRD 和 `docs/prototype/index.html` 之前，不继续写应用。

日期：2026-10-24。取代 `2026-10-23-unfold-prd.md`（已作废）。
读者：产品决策者本人。单用户，桌面 Web 优先，界面中文。
工作标题：Unfold。把一条推导展开，并让它留在体系里。

**与上一版的根本差异**：上一版以树形体系（领域→体系→阶段→章节→专题）为主入口，内容依附专题文档，对象靠「表达」绑进专题。2026-10-24 的反馈指出两条硬伤：

1. **整理复杂度太高。** 学习开始前要先决定一个点挂在树的哪个位置，这和真实学习顺序相反——真实学习是先有模糊的点，越学越清楚它该和谁放在一起。
2. **学习是扇形的，不是线性的。** 从一个点出发，沿不同角度挖：基本概念、概念间的联系、历史演进（a→b→c，每条边上是什么条件变了、行为为什么变）、不同 case。树形目录表达不了这种展开；脑图和 DAG 能表达结构，但承载不了节点里的推导、代码、表格和公式。

本版把主交互从「目录树 + 专题文档」改为「**焦点扇形**」：每个知识点既是有稳定身份的图节点，也拥有一份可渐进生长的块文档。以下逐节展开。

上一版中已确认且本版继续有效的内容，不再重复论证，直接引用：学习科学依据（提取练习、间隔、交错边界、自我解释、渐撤提示、迁移门槛）、能力与证据分离、建议托盘的人确认原则、AI 的职责边界、安全与隐私要求、工程形态（pnpm workspace、Fastify、Vite/React、Drizzle、PostgreSQL、自有文档 schema）。变更集中在：信息架构、核心交互、内容归属模型、块类型系统、合集取代体系树。

## 一、诊断（更新）

### 1.1 要解决的四个问题

**1. 点要能长出来，而不是先归位才能写。**
学习的真实顺序：先遇到一个模糊的点（一个概念、一道题、一个说法），围绕它追问，逐步补出演化来历、对照、变体和应用。产品必须允许一个点以「一句话核心陈述」的形态先存在，内容、关系、归位全部后补。任何「先选位置、先填字段才能保存」的设计都和这个顺序冲突。

**2. 扇形展开要有地方落。**
站在一个点上，自然的问题是：它从哪来（演化自什么、前置是什么）？它到哪去（演化出了什么、用在哪些问题上）？它和什么容易混（对比、类比）？条件变了会怎样（变体、失效条件）？这四个方向不是列表，是学习动作本身。界面要把四个方向做成常驻的、可点击的挖掘入口。

**3. 演进链上必须写「条件变了什么」。**
从 a 到 b 到 c，价值不在顺序而在边上：重复子问题被合并，所以决策树变成状态 DAG；目标从「全部方案」变成「最少刀数」，所以回溯换成 DP；物品可以重复选，所以背包内层循环换方向。链是产品结构里的一等视图，边上的条件变化是必填信息。

**4. 节点要承载复杂内容，图不行，文档行。**
脑图/DAG 负责结构和导航；节点本身要能装推导过程、代码、表格、公式、个人句子和疑问。不同学科装法不同：算法要题块和代码，数学要定理和公式，语言要句型和例句对照。所以内容单元是可扩展的类型化块，不是统一富文本。

上一版的三个问题（推导留得下来、身份稳定摆放可改、检验落到具体能力）仍然成立，不再展开。

### 1.2 已经确认的原则（沿用上版，新增两条）

沿用：知识体系是主体，视图是投影；先连续可读再结构化；关系必须有类型和说明；AI 提建议人做决定；重构是日常操作；客观知识与个人掌握分开；证据只用证据语言，没有百分比；单用户。

新增：

- **点先行，整理殿后。** 游离（未编入任何合集）是合法且常见的状态。归位是渐进动作，不是保存前提。
- **节点即文档。** 图上一个点，点开一份内容。摘要（核心陈述）默认可见，细节展开在后。不允许出现「图里一个点，正文在别处」的两栖状态。

### 1.3 设计矛盾与处理（更新）

| 矛盾 | 处理 |
| --- | --- |
| 扇形自由生长 vs 体系化组织 | 点是主体。合集是可选的编排投影，用来表达「这一批点按这个顺序学」。游离合法，合集可嵌套但不为难用户：一个平铺合集就够用。 |
| 图表达结构 vs 文档承载内容 | 分层：图投影只显示点的身份、类型、一句话摘要和带语义的边；内容在点的块文档里。图上点一下换焦点，内容随之切换。 |
| 脑图式展开 vs 屏幕空间有限 | 图投影只画焦点的一跳邻居，按方向分区摆放。第二跳靠转移焦点到达，不在同一张图上铺开。 |
| 想要演进链 vs 关系散落在各点 | 链不另存数据。evolves_from / variant 关系加上边上的 what_changed，查询时拉直成链。 |
| 学科内容形态不同 vs 统一编辑器 | 块类型注册表。基础块、学习块、学科块三层。新学科 = 注册新块类型与模板，核心模型不动。 |
| 整理成本低 vs 关系质量高 | 连接可以从扇区一键发起（预填方向和类型），说明字段按关系类型要求填写；其余字段（别名、能力、归位）全部可后补。 |
| 渐进深度 vs 复习调度需要结构 | 能力挂点，证据挂能力。点再小也能挂能力；点长大了，能力和证据不动。 |

上一版矛盾表中关于「专题上下文表达」「目录重构」的条目随模型更换而废止，其余（建议托盘不打断、虚假精度、三种复习、开放推导自评、跨领域同名、渐撤提示、局部图上限）原样保留。

### 1.4 学习习惯：保留与改造（更新）

保留：从具体问题追问到原理再用变体检验；探索留在外部对话里，产品负责沉淀；三种复习触发；对比与变体驱动。

改造：

- 「以体系树为入口」改为「以焦点为入口」。体系（合集）仍然是重要的组织成果，但它是长出来的，不是先搭好的。
- 「一题一篇笔记或一章一篇长文」改为「一个点一份渐进生长的文档」。长推导可以住在一个点里，也可以拆成一条链上的几个点，由边上的条件变化连接。
- 整理动作从「保存前分类」改为「学习间隙顺手连接」。每天打开看到的游离点数就是整理债务的诚实度量。

### 1.5 有学习价值的机制 vs 看起来高级的东西（沿用）

结论不变：提取、间隔、渐撤提示、自我解释、基于已写明对比的辨别、迁移门槛，做成机制；全库图、三维图、自动拆节点、掌握度分数、通用聊天、多 Agent，不做。本版新增一条：**图投影是导航，不是装饰**——如果某个图视图不改变下一步点击，它就不该存在。

## 二、产品架构备选与推荐

### 方案 A：树形体系为主（上一版）

领域→体系→阶段→章节→专题，内容依附专题文档。优点：编排清晰，路径明确。致命伤：保存前先归位，整理复杂度挡在学习前面；扇形挖掘（同时沿四个方向展开）在树上没有对应动作；演进链要跨章节横切。用户已否决。

### 方案 B：白板/脑图为主

节点卡片摆在无限画布上，连线表达关系。优点：扇形展开直观，空间记忆好。致命伤：节点承载不了长推导和代码；位置本身不是知识身份，两次重构后白板变成垃圾场；复习、证据、搜索都难挂靠。Heptabase 类产品的已知边界，用户已否决。

### 方案 C：焦点扇形（推荐）

**一次只有一个焦点，点即文档，方向即动作。**

1. **点（KnowledgeObject）**：有稳定 ID、类型、领域、一句话核心陈述，以及一份自己的块文档。块文档从空开始，随学习生长。点可以不属于任何合集（游离）。
2. **扇形**：焦点页的关系面板按方向分四个扇区——来历（演化自、前置）、去向（演化出、应用于、实现）、对照（对比、类比）、变化（变体、失效条件）。每条连接显示边上的说明（什么条件变了）。点击连接 = 焦点转移。
3. **链**：演化与变体关系拉直成横向链视图，边上是条件变化。不另存数据。
4. **图投影**：以焦点为中心的放射局部图，一跳邻居按扇区方位摆放，节点带摘要，点击换焦点。节点上限 50。
5. **合集（Collection）**：轻量编排。一份块文档，里面用对象引用块把一批点组织成学习顺序，引用块周围写上下文讲解。合集可嵌套，但平铺即可用。合集也是上一版「专题」和「体系树」的共同替代。
6. **块（Block）**：类型化内容单元。基础块 + 学习块 + 学科块，类型可注册扩展。块是引用和粘贴的最小单位。

为什么是 C：扇形挖掘直接映射真实学习动作（从一个点沿角度展开）；点即文档解决「脑图承载不了内容」；合集把「体系化」保留为可选成果而不是前置劳动；块类型系统解决学科差异；渐进生长解决整理复杂度。A 的编排能力和 B 的空间感都作为投影保留（合集、图投影），但都不再做主体。

日常形态：

打开应用，今日页给出当前焦点和该复查的能力。进入焦点，看见这个点的一句话核心陈述、已生长的内容块、四个方向扇区。粘贴来自 GPT 的材料，直接长在当前焦点上（或顺手新建一个点）。建议托盘只提连接，不提分类。想成体系时，把一批点拖进一个合集，顺序就是学习路径。

## 三、产品战略

### 3.1 产品定义

Unfold 是个人的知识星图与能力成长系统。知识点以稳定身份存在，内容以可扩展的块承载，关系以带方向语义和条件说明的边连接，学习以焦点扇形的方式展开，检验以能力和证据闭环。

### 3.2 目标用户

不变：约十年经验的软件架构师。领域当前是算法、AI Agent、系统设计，已明确会扩展到数学、英语等不同形态的知识。原理驱动，内容主要从外部对话沉淀。

### 3.3 产品价值（更新）

- 一个点可以在三十秒内开始存在（一句话 + 粘贴），在数周内长成带推导、对照、变体和证据的完整节点。
- 概念之间的联系写得出「条件变了什么」，并且沿链能重走。
- 不同学科的知识用各自合适的块形态放进同一张图。
- 整理债务可见（游离点数），但永远不挡学习。
- 上一版的价值（身份稳定、证据落能力、边界类比、判断可找回）全部保留。

### 3.4 产品边界（更新）

做：点与块文档、四向扇形、链视图、局部图投影、合集编排、粘贴与建议托盘、能力练习与三种复习、跨领域类比边界、块类型扩展。

不做：无限画布白板、全库图、题库、多人协作、通用聊天、自动拆节点、百分比。

### 3.5 与相邻产品的差异（更新）

| 产品 | 它解决的问题 | Unfold 不同的地方 |
| --- | --- | --- |
| Obsidian / Logseq | 快速捕获、双向链接 | 链接无语义，点没有类型化块和核心陈述，检验无挂靠 |
| Heptabase / Muse / 脑图 | 空间结构 | 节点承载不了长内容；位置不是身份；没有学习闭环 |
| Notion | 数据库 + 页面 | 页面与库两套东西；关系没有方向语义和条件说明 |
| RemNote / Anki | 卡片间隔重复 | 最小单元是能力原句不是卡片；开放推导自评；点是生长中的文档 |
| Capacities / Tana | 类型化对象 | 对象优先挡在粘贴前面；这里点可以先是一句话 |
| 上一版 Unfold | 体系化学习 | 树形归位是前置劳动；扇形挖掘和演进链没有主交互 |

## 四、核心模型

### 4.1 点（KnowledgeObject）

五种类型不变：concept / principle / method / model / problem。

每个点拥有：

- 稳定 ID、类型、领域、规范名、别名。
- **一句话核心陈述**：创建时唯一被鼓励立即填写的内容。图上和扇区里显示的就是它。
- **一份块文档**：从空开始生长。推导、代码、表格、疑问、个人理解都住在这里。
- 关系边（出与入）。
- 能力与证据（可后补）。
- 归位状态：游离，或被若干合集引用。

点的生命周期：**种子 → 生长 → 检验**。种子=一句话；生长=块内容和边增多；检验=能力有了独立证据。三个阶段不设门槛，界面用证据语言描述，不打进度条。

### 4.2 扇形：关系按方向分区

关系词表沿用上版十一种，按扇区分组：

| 扇区 | 关系 | 边上必须写 |
| --- | --- | --- |
| 来历 | evolves_from（反向读）、prerequisite | what_changed（演化必填） |
| 去向 | evolves_from（正向读）、applies、implements | condition（应用建议写） |
| 对照 | contrasts、analogous | distinction（对比必填）、boundary（类比必填） |
| 变化 | variant、fails_when | what_changed / condition（均必填） |

扇区不是新数据结构，是词表的界面分组。扇区里的每一条都可点击转移焦点。

### 4.3 链（Chain）

evolves_from 与 variant 的线性投影。查询时从焦点沿同类边向两端走，拉直成横向序列，每条边渲染 what_changed。例：

决策树 —（重复子问题被合并）→ 状态等价 —（第一次算完就记住）→ Memo —（按依赖反方向填表）→ Bottom-up

LC131 —（目标变成最少刀数）→ LC132；LC139 —（目标变成全部拆法）→ LC140。

链是只读投影。链上每个点可点击换焦点。不写第二份「链数据」。

### 4.4 合集（Collection）

上一版的体系树（领域/体系/阶段/章节/专题）整体替换为合集：

- 合集有一份块文档，用**对象引用块**把点组织进来，顺序即学习路径。
- 引用块周围可以写上下文：为什么这个点在这个位置、在这个合集里要这样理解它。这就是上一版「一个身份、多份上下文表达」的落地方式——上下文写在合集文档里，身份和核心内容留在点上。
- 合集可嵌套（合集引用块），但默认平铺。不限制层级种类，没有「阶段/章节/专题」的类型约束。
- 点被合集引用不改点的任何字段。从合集移除点只是删一个引用块。

### 4.5 块（Block）

内容的最小单元，带稳定 UUID。三层类型：

**基础块**：标题、段落、列表、引用、表格、代码、公式（KaTeX）、图（Mermaid）、图片、分隔。

**学习块**：推导步骤（有序，供链/脊投影使用）、分级提示（默认折叠，供练习）、个人理解、疑问、反例、决定（含放弃的方案与理由）。

**学科块**（可扩展）：

- 算法题块：题面、约束、样例、复杂度字段。
- 定理块：命题、条件、证明、推论。
- 句型块：句型、例句、对照、易混点。

块类型注册表定义每种类型的字段、渲染器、粘贴解析规则和导出形式。新增学科 = 注册新块类型 + 模板，不动点、关系、证据模型。第一版学科块可以是「带字段模板的复合块」，渲染先朴素，验证形态后再加深。

**引用块**：对象引用块（转写，活引用）与合集引用块。复制并断开产生新块，记 `derived_from_block_id`。

### 4.6 能力与证据（不变）

Capability（一句可观察的能力）、Evidence（不可变学习事实）、ReviewState（证据重放的调度缓存）原样保留。能力挂点，可跨点。八种 kind 共用一个练习骨架。提示阈值、迁移门槛、证据语言全部沿用。

## 五、用户旅程（重写）

### 5.1 场景 A：从 GPT 长出一个点

触发：在 ChatGPT 里追问完「状态等价」，复制一段含推导、表格、JS 代码和个人句子的回答。

步骤：

1. 在算法领域新建点「状态等价」（一句话核心陈述 + 类型 concept，仅此而已），或粘贴时让系统建种子。
2. 粘贴。同步保存为块：段落、2×3 表格、JS 代码块、个人句子块。脚本和事件属性不进入。
3. 右侧托盘出现连接建议（最多 5 条）：认出已有「决策树」，建议演化关系并预填 what_changed；认出「记忆化搜索」，建议实现关系；个人句子建议挂为点的个人理解块；「最优子结构」与「重叠子问题」建议建成对比（禁止建议合并）。
4. 逐条接受、先不、忽略。接受后扇区立即出现对应方向的连接。
5. 这个点此刻是游离的。不提示归位。

反馈：保存有确认；每条建议在扇区产生可见变化。

异常：解析失败仍存纯文本；模型不可用则规则建议照常；无命中时托盘明说「这次没有连接建议」。

成功：点存在，内容保真，扇形四个方向里至少来历和对照不再是空的。归位与否不影响任何后续动作。

### 5.2 场景 B：扇形挖掘

触发：读完「状态等价」的核心陈述，想往深处走。

步骤：

1. 焦点页，四个扇区可见。来历：决策树（重复子问题被合并）。去向：Memo、LC139、LC140。对照：回溯×DP 的对比入口、最优子结构×重叠子问题。变化：LC131→LC132 变体链。
2. 点「决策树」，焦点转移，看到这个点的文档；图投影里焦点换位，邻居重排。
3. 切到链投影，把「决策树→状态等价→Memo→Bottom-up」整条走一遍，边上每句条件变化都在。
4. 走到 Memo 时发现它还没有「演化出 Bottom-up」的边，从 Memo 的去向扇区一键发起连接，预填方向，补上 what_changed。

反馈：焦点切换时面包屑显示路径（状态等价 ← 决策树），可回退。

成功：一次学习在点之间流动完成，没有打开过任何目录树；新连接当场补建，无需离开焦点页。

### 5.3 场景 C：整理——把一批点编成一个合集

触发：学了数周后，「状态等价」「记忆化搜索」「LC139」「LC140」「最优子结构」等点都在，想形成「状态等价与状态空间压缩」的学习顺序。

步骤：

1. 新建合集，写一句编排意图。
2. 把点逐个拖入（或从点的「归位」面板选合集），顺序可拖。引用块出现在合集文档里。
3. 在引用块之间写上下文段落：这个合集里先读谁、为什么。
4. 误操作撤销（结构命令日志不变）。

反馈：执行前后显示点的 ID 和证据条数不变；点可以同时出现在多个合集里。

成功：合集成为一条可读的学习路径。点还是那些点，游离数减少。上一版的「移动/转写引用/复制断开」语义保留在块层：合集文档里引用是活的，复制段落则断开。

### 5.4 场景 D：学习陌生题目（LC140）与失败回查（LC862）

机制与上版一致，入口变化：

- LC140 是一个 problem 点。题面块不含算法类别。提示是折叠的学习块。练习从点的能力进入，失败记障碍原文，挂在能力上。
- LC862 失败后回查的是能力原句「队列只保留对未来有贡献的下标」，挂在原理「候选支配」上。复习页先独立说出、分级提示、重写解释、重算复查日。

### 5.5 场景 E：跨领域类比

不变：搜索「状态」分域并列返回；并排打开；analogous 边必填 boundary；没有合并入口。入口变化：从任一点的「对照」扇区进入并排视图。

### 5.6 场景 F（新）：换一个学科

触发：开始学数学（导数）和英语（句型）。

步骤：在对应领域新建点；编辑器里插入定理科/句型块；块的字段是该学科的模板；点的扇形、链、能力机制和算法领域完全一样。

成功：新学科没有要求新的核心模型，只多了块类型。游离列表里出现这些新点，等想编排时再归位。

### 5.7 其余旅程

查找（对象分组、疑问与决定命中、专题里的句子可提升）、主动复习（三种触发）、核心陈述变更后的待确认（改为：引用该点的合集文档提示「核心定义已更新」，逐处确认）——机制沿用上版，数据归属改为点。

### 7.3 图投影

以焦点为中心的放射图：来历在左，去向在右，对照在上，变化在下。节点显示名称、类型标记、一句话摘要（截断）。点击节点 = 换焦点。只画一跳，上限 50。它是导航，不是装饰画。

### 7.4 链投影

经过焦点的演化链与变体链横向展开，边上写条件变化。多条链可切换。点可点击。数据全部来自关系表。

### 7.5 对比并排

从「对照」扇区进入：两点并排核心陈述 + 矩阵（对比）或边界段（类比）。类比并排保留「不提供合并」的硬性约束。Retry/Resume/Replay 挂在 Agent 侧作为方法对比。

### 7.6 合集页

一份带引用块的连续文档。引用块显示点的名称 + 一句话核心陈述，点击进点。引用块之间是上下文段落。拖拽改顺序（改的是引用块位置）。头部显示合集意图。「游离的点」可以从这里或今日页拖入。

### 7.7 练习与复习

与上版一致：题面/能力原句先行，材料被挡住；提示逐级；第 3 级锁独立；自评；障碍原文；证据落能力。返回入口：回到点（对应块位置），或把障碍挂为点的疑问块。

### 7.8 键盘（沿用并补充）

⌘K 搜索；`[` `]` 切换投影；⌘Enter 保存；⌘Z 撤销结构命令；练习里 1–4 展开提示；托盘里 A 接受 S 延后；焦点页里 ← → 沿扇区转移焦点（在选中连接上回车进入）。

## 八、知识数据模型（重写变更部分）

### 8.1 实体表

| 实体 | 职责 | 不做什么 |
| --- | --- | --- |
| User | 所有者 | 第一版只有一个 |
| Domain | 领域，防误合并，供搜索分组 | 不阻止跨领域关系 |
| KnowledgeObject | 点：稳定身份 + 一句话核心陈述 | 不再只是身份，**它拥有主文档** |
| Document | 点的块文档（每点一份） | 不挂合集，合集有自己的文档 |
| Block | 块索引（含类型） | 不把每块变成对象 |
| BlockType | 块类型注册表（概念性，代码常量即可） | 不做成用户可改的 UI 配置 |
| Collection | 合集：编排意图 + 一份含引用块的文档 | 不拥有点；不是权限边界 |
| Relation | 带类型边，字段同上版（what_changed/distinction/condition/boundary/note/status/origin） | 不表示「相关」 |
| Capability / Evidence / ReviewState | 不变 | 不变 |
| Annotation | 大部分并入学习块；保留 target 为 relation/capability 的注解 | 不再承载「个人理解块」能做的事 |
| Source | 一次粘贴/导入 | 不变 |
| Revision | 结构命令日志（合集归位、块移动/转写/复制、合并、软删） | 不变 |

**被移除的上一版实体**：KnowledgeSystem、OutlineNode、Expression。体系树由 Collection 取代；「表达」由「点的文档 + 合集文档里的引用块与上下文」取代。Expression 的核心验收语义保留并改述：

- 同一规范名的活跃对象仍是一行，多个合集引用同一个 ID。
- 各合集上下文互不覆盖：上下文写在自己的文档里，改一处不影响他处。
- 核心陈述版本更新时，通过块索引反查引用该点的合集，逐处标「核心定义已更新，待确认」。确认只改该合处的已读版本。

**Document** 字段不变（schema_version、content_json、plain_text、saved_at、30 次保存点），所有者变为点或合集（owner_type/owner_id）。

**BlockIndex** 增加 `block_type`。学科块的结构化字段存 content_json 的块属性里，不另建表。

**Collection**：`id, user_id, domain_id, title, intent, document_id, parent_collection_id（可空，一层嵌套够用就做一层）, position`。

**KnowledgeObject** 增加 `core_version`（已有）、`document_id`。名称唯一性、别名唯一性、合并/拆分/软删规则沿用上版。

### 8.2 关键约束（更新）

- 点可以零合集引用（游离合法）。合集文档里的对象引用块必须指向活跃对象；对象合并时引用块跳到保留 ID。
- 删除仍被合集引用或仍有已接受关系的点：拒绝并返回计数，用户确认「解除并删除」后软删。
- 类比边界非空；类比两端不进合并候选。
- 提示层级与独立完成互斥；迁移门槛；只有 accepted 关系进扇区、图、链。
- 块类型必须在注册表内；粘贴解析按块类型的规则走；服务端用同一 schema 再校验。

### 8.3 生命周期（点的视角）

创建：一句话核心陈述 + 类型 + 领域。生长：粘贴、写作、扇区连接、建议接受，全部增量。归位：被合集引用，可多次。检验：能力挂点，证据挂能力。合并/拆分/删除：沿用上版规则，引用块随合并跳转。

## 十二、MVP

闭环更新为：

**粘贴长出一个点（一句话 + 块内容）→ 沿扇形挖出两三个连接并写条件 → 用链投影重走一遍 → 做一次练习或登记一次失败 → 证据落能力 → 今日里再遇到这条能力 → 想成体系时把点拖进合集。**

页面清单：今日、焦点页（含内容/链/对比/能力投影与扇区、托盘、归位面板）、合集页、练习/复习页、搜索面板。

## 十三、技术架构（沿用，补充块渲染）

栈不变：pnpm workspace、Vite 6/React 19/TypeScript 5.9、Fastify 5、Drizzle/PostgreSQL、自有 doc-schema、`ts-fsrs`、argon2 Cookie、Vitest。不引入图库布局框架（图投影节点位置由扇区方位 + 序号计算，坐标是纯函数）。

## 十四、分阶段路线

- 验收：场景 A、C；点入多合集 ID 不变；撤销恢复；导出再导入 ID 保留。
- 不做：图投影。

### 阶段 4：学习闭环

- 交付：能力、练习页、分级提示块、证据、调度重放、今日页、失败登记、薄弱前置。

- 验收：场景 F；图只画一跳且点击换焦点；学科块在粘贴/导出中往返不丢字段。

## 十五、验收标准（更新）

沿用上版中仍然成立的条款（建议托盘、证据、保真、恢复的绝大部分），身份与表达一节改述为：

1. 创建「状态等价」。三个合集各引用它。活跃对象 1 行，三个合集文档解析到同一 ID。
2. 三个合集的上下文段落互不影响；改一处，另两处文档哈希不变。
3. 修改核心陈述，引用该点的合集都显示待确认；确认一处只改该处已读版本，点与合集正文不变。
4. 点从零合集（游离）状态可以被完整使用：粘贴、连接、练习、被搜索到。
5. 点被编入两个合集后，点的 ID、关系、证据条数不变；从一个合集移除不影响另一个。
6. 链投影渲染的边文与关系表中的 what_changed 逐字一致；链上不出现未接受的关系。
7. 扇区面板只显示已接受关系；点击任意一条，焦点切换到目标点。
8. 新增一个块类型（注册表 + 渲染器 + 解析器）不需要改动点、关系、能力、证据的任何表结构。

## 十六、学习效果与产品指标（更新）

保留上版指标，新增/替换：

- **游离点数与游离时长**：不是越低越好，而是「想学时不被归位挡住」；若游离点长期不增长也不归位，说明合集没有价值，要简化合集而不是加提醒。
- **扇形使用**：每周通过扇区转移焦点的次数；长期为零说明扇形没有进入真实学习，图投影更不该做。
- **边上说明质量**：带 what_changed/distinction/boundary 的关系占比；趋低说明连接在退化成语义不明的「相关」。
- **点的生长曲线**：从种子到有第一份证据的间隔；从创建到首次被合集引用的时间。
- 粘贴到可用的动作数（目标：保存 + 逐条建议，无强制字段）。
