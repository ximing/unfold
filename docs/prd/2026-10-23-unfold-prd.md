## 一、诊断

### 1.1 要解决的三个问题

**推导留得下来，而且以后还能按原顺序重建。**
学习发生在外部 ChatGPT 里。有价值的是整段推导，不是最后一句定义。DP 要留下的顺序是：决策树 → 状态 → 状态等价 → 状态合并 → DAG → Memo → Bottom-up。中间有表、公式、代码，也有自己的一句判断。产品要先把这段原样收下，再让它能被再次展开。

**知识有稳定身份，摆放可以随时改。**
整理方式是领域 → 体系 → 阶段 → 章节 → 专题。这个树会经常拆、并、重挂。文件路径和章节不是知识的身份。同一个「状态等价」在 DP 专题里讲决策树合并，在图搜索专题里讲 visited，核心身份只有一个，两处正文各写各的。算法里的「状态」和 Agent 里的「状态」同名，是带边界的类比，不是同一个对象。

**学习要能被检验，检验要落到具体能力。**
看懂一段解释，和能独立判断「哪些历史影响未来」，不是同一件事。LC862 做不出来，失败的往往不是「单调队列这个专题」，而是「队列只保留对未来有贡献的下标」或队尾淘汰条件。证据挂在能力上。阅读次数、节点数量、收藏数量不代表掌握。不使用未经验证的掌握度百分比。

### 1.2 已经确认的原则

- 知识体系是主体。文档、目录、关系图、对比矩阵、变体链、推导视图、能力清单，都是同一套数据的投影。
- 先保证连续正文能读、能贴、能重组，再把少数高价值片段提升为对象。不把每句话拆成卡片。
- 关系必须有类型、方向，以及该类型所要求的说明。不存在无语义的「相关」。
- AI 提出结构建议，人逐条决定。建议可以延后。模型失败时，手工编辑仍然完整。
- 重构是日常操作。对象 ID、关系、学习证据跟着身份走，不跟着目录走。
- 客观知识和个人掌握分开存。掌握只由证据描述，不合成一个分数。
- 单用户。表上保留 `user_id`。不把整个知识库发给模型。

### 1.3 设计矛盾，以及本文的处理

| 矛盾 | 处理 |
| --- | --- |
| 连续推导 vs 可复用身份 | 专题文档是阅读正文。知识对象是被确认的身份。上下文表达只记录「这些块在这个专题里讲解这个对象」。 |
| 重构自由 vs 引用完整 | 移动的是大纲节点或块。对象、关系、能力、证据不改 ID。结构操作可撤销。 |
| 想要语义关系 vs 不想被对话框打断 | 粘贴先保存。建议出现在正文旁边的托盘里，一次最多 5 条，逐条接受、延后或忽略。不弹多层对话框。 |
| 想知道自己会不会 vs 虚假精度 | 展示能力原句、最近一次证据、建议复查日。三者不合成百分比。 |
| 三种复习都要 vs 不想只剩闪卡队列 | 到期复查、做题失败后回到那一条能力、打开专题时带上最多 3 条薄弱前置。重读原文发生在回忆失败之后。 |
| 开放推导无法可靠判分 vs 间隔算法需要结果 | 开放回答由用户自评。提示展开到第 3 级及以上，这次不能记为独立完成。调度器只决定何时再问。 |
| 跨领域同名 vs 错误合并 | 默认识别为类比。类比必须写适用边界。界面不提供合并。 |
| 新手需要例题 vs 会了以后例题碍事 | 提示默认折叠。该能力已有独立通过记录时，下次不自动展开提示。 |
| 多视图有用 vs 全库图没有用 | 视图都做，数据只有一份。关系图只画当前专题或当前对象的邻居，可见节点不超过 50。不做三维图，不做全库力导向图。 |

### 1.4 学习习惯里保留的，和要改的

保留：

- 从具体问题追问到原理，再用变体检验。顺序例子：LC139 → 状态等价 → 再用 LC140 检验。
- 以体系为入口，并直接改这棵树。
- 探索留在外部对话里，产品负责沉淀。
- 复习可以是计划中的、做题触发的、学新内容时带上的。

改：

- 读完只表示正文在库里，不写掌握记录。
- 失败写成一项能力。当时还没有这项能力，就在失败现场创建它。
- 对比和变体在学习时写成带「条件变了什么」的关系，供以后的辨别使用。
- 个人的一句话挂到已有对象上，不因此新建一个概念。

### 1.5 有学习价值的机制，和只是看起来高级的东西

做成机制：

- 不看材料的回忆、解释、推导。
- 隔一段时间再次提取。间隔随希望保持的时间和上次表现变化。
- 只在用户写过对比或变体的对象之间做辨别。新内容先集中学。
- 分级提示，然后撤掉。
- 自我解释：为什么成立，为什么别的方法不行，哪个条件决定了选择。
- 把「看懂了」和「独立做到」分成不同证据。

不做，也不当成产品中心：

- 全库图谱、三维图谱、自动生成大量节点。
- 掌握度分数、积分、排行榜。
- 自动判断开放式推导的对错。
- 应用内的通用聊天，用来替代 ChatGPT。
- 自主多 Agent。
- 为个人规模引入图数据库或微服务。

### 1.6 学习科学依据

直接写成产品规则的证据：

- 提取练习和分散练习是高效用方法。重读、划线是低效用方法（Dunlosky 等，2013）。测验本身强化长期保持（Roediger 与 Karpicke，2006）。对科学短文，提取练习在理解题上优于只做概念图（Karpicke 与 Blunt，2011）。后一项研究的学习时间不完全相等，所以它只支持「只整理、不提取，不足以产生掌握」，不支持「概念图无用」。
- 最佳间隔随希望保持的时间变长而变长（Cepeda 等，2008）。产品用随表现调整的间隔，不用固定的 1-3-7 天重读。
- 读起来顺不等于会了（Bjork 的合意困难；Koriat 与 Bjork，2005）。

有边界地使用：

- 自我解释的提示大约 g = 0.55（Bisra 等，2018）。产品用固定提示语。
- 交错练习总体大约 g = 0.42，数学材料大约 g = 0.34（Brunmair 与 Richter，2019）。说明性文本上不稳定。只对已经写明的对比和变体交错，新专题默认集中。
- 新手先看样例，再逐步撤掉步骤（Sweller；Renkl）。已经会的人继续铺满例题有害（Kalyuga 等，2003）。提示默认折叠。
- 测试式学习对迁移大约 d = 0.40，但远迁移不是默认结果（Pan 与 Rickard，2018；Barnett 与 Ceci，2002）。迁移任务在源能力至少有一次独立通过之前不开放。

标成产品假设，不是实验结论：

- 把证据挂在能力上，能让 LC862 这种失败回查更准。
- 在事实卡片上拟合的 FSRS，用来决定「何时再问一条推导能力」，会比固定天数更合适。间隔效应本身证据强。这个外推没有同样的基准。到期日是建议，可以提前复习。参数用默认权重、目标保持率 0.9、最长间隔 180 天。不设 Easy，不设当日短间隔。
- 一次最多 5 条、可逐条拒绝的结构建议，能提高关系质量，同时不把学习打断掉。

## 二、产品架构备选与推荐

### 方案 A：文档优先

专题是文件，链接是关系，目录等于文件夹。捕获最快，长推导最完整。两轮重构之后，身份跟着路径走，上下文解释分叉，学习证据挂在文件上。这就是「有双向链接的 Markdown」，原始说明已经排除。

### 方案 B：对象优先

打开应用就在填类型化对象，正文是对象的一个字段。身份稳定，但录入时的认知负荷和「先粘贴、后整理」相反。长推导和「这句话只在这个专题里这样讲」会变成次要内容。也容易滑向自动生成大量节点。

### 方案 C：编排、身份、证据分开（推荐）

1. **编排层。** 体系是一棵可重挂的大纲。节点是阶段、章节或专题，种类是标签，不限制父子组合。专题有一份连续文档。学习顺序写在这棵树上，不写在对象 ID 里。
2. **身份层。** 知识对象有稳定 ID、类型、领域、核心陈述、别名。上下文表达把对象绑到某份文档的若干块上。关系是带类型的边。
3. **证据层。** 能力用一句话写「能做什么」。练习留下不可变证据。复查日由证据重放得到。

捕获走方案 A 的手感：贴进专题，立刻能读。身份走方案 B 的规则，但只在人确认后生效。证据层用来完成学习闭环，不把产品做成刷题软件。

这就是已经确认的三层：专题体系、知识网络、能力与证据。再加上「一个身份、多份上下文表达」。

推荐的日常形态：

打开应用，先看到当前体系位置和一句还没检验的能力，而不是统计数字。阅读时，推导顺序留在左侧，正文保持连续，右侧是这个专题已经确认的对象、关系和能力。粘贴之后，建议停在托盘里。练习从能力或题目进入，失败写回那一条能力，并能回到原来的推导。

## 三、产品战略

### 3.1 产品定义

Unfold 是个人的知识体系与能力成长系统。它映射、组织、关联、重构一套会继续演化的知识，并用可复查的练习把知识变成能够独立使用的能力。

它同时是知识系统（身份、语义关系、可组合、可重构）和学习系统（提取、间隔、辨别、渐撤提示、迁移）。两边共用一套数据。

### 3.2 目标用户

具有约十年开发和系统架构经验的软件架构师。当前领域是算法与数据结构、AI Agent、软件架构与系统设计。以后可以扩展到数学和其他技术学科。抽象能力强，要求原理，不满足于步骤模板。内容主要从外部对话沉淀进来，而不是在应用里从零写完。

### 3.3 产品价值

- 新的推导能进入已有体系，而不是再开一篇孤立笔记。
- 概念之间的联系写得出「为什么」，并且能在重构后还在。
- 自己的判断、疑问、曾经的错误认识和认知突破留在对应的对象上。
- 能指出哪一条能力有独立证据，哪一条只是读过，哪一条上次失败在哪个条件上。
- 面对陌生问题时，能沿依赖、变体和类比边界回到该用的原理。

### 3.4 产品边界

做：

- 多领域、多套体系、可重构的阶段 / 章节 / 专题。
- 连续文档，保住标题、推导顺序、表格、代码、公式、图、个人句子。
- 知识对象、上下文表达、有类型的关系。
- 粘贴后的结构建议，逐条确认。
- 同一模型的多种投影：正文、推导、对比、变体、局部关系、能力清单。
- 围绕能力的练习、三种复习触发、失败回查。

不做：

- 通用聊天产品。
- 题库和判题平台。LeetCode 只保存用户写下的题号、标题、链接和个人推导，不导入题目原文库。
- 多人协作、社交、积分。
- 自动把全文拆成节点。
- 用一个百分比代表掌握。

### 3.5 和相邻产品的差异

| 产品 | 它解决的问题 | Unfold 不同的地方 |
| --- | --- | --- |
| Markdown 笔记、Obsidian、Logseq | 快速捕获，双向链接 | 链接没有语义。重构文件会带走身份。没有「能力证据独立于正文」。 |
| Notion | 数据库和页面 | 页面和数据库是两套东西。推导、关系和练习对不上一个身份。 |
| RemNote | 笔记里的间隔重复 | 复习单元接近卡片和挖空。这里的最小单元是一条能力，开放推导不自动判分。 |
| Anki | 事实的长期保持 | 调度思想可借鉴。产品不是卡片堆，也不把 SM-2 的三档回忆当成推导评分。 |
| Heptabase、Muse | 白板上看见结构 | 白板位置不是知识身份。长推导和复查证据不是它的中心。 |
| Capacities、Tana | 类型化对象 | 对象优先会挡在粘贴前面。这里先收正文，再确认身份。 |
| 图数据库浏览器 | 画出节点 | 图是局部投影。边必须有类型。没有全库头发团。 |

### 3.6 为什么这套方案对得上学习目标

身份和编排分开，重构才不会制造第二份「状态等价」。表达按专题分开，DP 和图搜索可以讲不同的例子，搜索又还能回到同一个对象。能力单独记账，LC862 的失败不会把整章打回。建议托盘让 GPT 正文在保存时就被认出来，同时不会未经同意改写体系。对比矩阵和变体链直接服务于「条件变了什么、方法为什么换」，而不是事后从全文里猜。

## 四、用户旅程

每条旅程都包含触发、步骤、反馈、异常和成功结果。场景 A 到 E 写完整交互。原型里每条都有对应屏幕。

### 4.1 场景 A：从 GPT 沉淀「状态等价」

触发：在 ChatGPT 里追问完 DP，复制一段含有推导、表格、JS 代码和个人句子的回答。

步骤：

1. 在「算法本质训练体系 / 阶段一 / 从决策树到状态空间」打开专题，粘贴。
2. 系统同步保存。标题、顺序、2×3 的表、JS 缩进、公式、Mermaid 源码、句子「如果两个历史对未来没有影响，它们就是同一状态。」都在。脚本和事件属性不进入文档。
3. 保存完成后，右侧托盘出现最多 5 条建议，正文保持可编辑。
4. 建议一：文中的「状态等价」是已有对象。把这些块标成它在本专题的推导表达。操作：接受，或先不。
5. 建议二：与「决策树」建立演化关系。变化条件预填「重复子问题被合并成同一状态」。接受前可以改这句。
6. 建议三：与「记忆化搜索」建立实现关系。
7. 建议四：那句个人判断挂到「状态等价」的个人理解上，不新建对象。
8. 建议五：文中同时出现「最优子结构」和「重叠子问题」。这是两个原理，建议建立对比。不建议合并，也不把它们写成别名。
9. 逐条处理后可以继续改正文。延后的建议留在「稍后」，不挡阅读。

反馈：每条建议接受后，托盘该项变为已接受，右侧身份账本立即出现对应对象或关系。忽略的项不再出现，除非正文里的名称发生了变化。

异常：

- 解析失败时，仍保存纯文本副本，并提示哪一块没有结构化。用户可以重贴或当普通段落编辑。
- 模型不可用时，名称和别名的规则建议照常出现。模型才会给出的关系建议标为暂缺。手工添加关系的入口始终在。
- 没有任何命中时，托盘写「这次没有结构建议」，正文已经保存。

成功：专题里有完整的表和代码。`状态等价` 仍是原来的 ID。本专题多了一条角色为「推导」的表达。决策树、记忆化搜索的关系是逐条接受的。个人句子挂在对象上。以后从对象页能列出所有引用它的专题。

### 4.2 场景 B：把「状态等价」移出「动态规划」

触发：认识到按 DP / 回溯 / 贪心分类不如按「状态等价与状态空间压缩」组织。

步骤：

1. 新建专题「状态等价与状态空间压缩」，挂到阶段一。
2. 对原专题里的推导选择一种动作：
   - **移动**：块离开原处，出现在新专题。对象 ID 和证据不动。
   - **转写引用**：新专题引用原来的块。两边读到同一块，改一处另一处跟着变。
   - **复制并断开**：新块，属性里记下来源块 ID。之后各改各的。
3. 调整章节顺序。拖拽改变的是大纲 `position` 和 `parent_id`。
4. 若误操作，撤销上一条结构命令。

反馈：执行前用一句话说明 ID 和证据会怎样。执行后展示对象 ID、证据条数、新的父节点。三者里，前两个应与执行前相同。

异常：移动会拆散一条表达时，先列出将要断开的块，用户确认后才执行。删除仍被引用的对象会被拒绝，并给出引用计数。

成功：新专题能读到推导。`状态等价` 的 ID 不变。原有关系还在。过去的复习记录还挂在原来的能力上。目录里不再把这段知识只放在「动态规划」下。

### 4.3 场景 C：学习 LC140，先不被告知算法类别

触发：要用一道新题检验「状态等价」，而不是再读一遍定义。

步骤：

1. 从专题或今日进入 LC140。题面只有问题：把字符串拆成字典中的单词，返回所有方案。界面不写「动态规划」「记忆化」。
2. 先看本专题的前置是否有到期能力。若有，最多露出 3 条，可以先做，也可以留下继续看题。
3. 用户写下：决策是什么，做到哪一步可以停。
4. 需要时逐级打开提示：
   1. 先写暴力递归：从当前位置尝试每一个能匹配的单词。
   2. 递归树里，相同前缀被重复展开。
   3. 状态是处理到下标 i。再往下看，这次就不能记为独立完成。
   4. 用记忆化或自底向上保存每个 i 的全部拆法。
5. 用户自评：独立完成、有提示地完成、没做出来。提示达到第 3 级时，「独立完成」不可用。
6. 若失败，记录具体障碍，而不是「LC140 失败」。例如：没看出相同前缀被重复展开；把「全部方案」误当成「最少拆分数」；状态写成了整段子串而不是下标 i。
7. 可以把这次理解挂回「状态等价」或「记忆化搜索」。

反馈：证据写入对应能力，带提示层级和障碍原文。今日页之后显示的是这句障碍，不是题号失败。

异常：这道题还没有能力目标时，用障碍原文创建一条能力，再把证据挂上去。不创建「LC140 掌握度」。

成功：用户要么留下一次独立或带提示的尝试，要么留下一条可复查的具体障碍，并且能从这条证据回到专题正文。

### 4.4 场景 D：LC862 失败后回到队尾淘汰

触发：重做 LC862，说不清单调队列为什么淘汰队尾。

步骤：

1. 登记失败。系统不把「单调队列」或整章标成未掌握。
2. 若已有能力「队列只保留对未来有贡献的下标」，证据挂在这条上。若没有，用这句话创建能力，并让用户确认它主要属于原理「候选支配」。
3. 练习先要求独立说出队尾淘汰条件。提示按级折叠：队列里下标的单调性、新下标进来时谁对未来已经没有贡献、和滑动窗口左边界的区别。
4. 用户重写一句自己的解释，挂到该原理在原专题中的个人理解上。
5. 这条能力进入后续复查。间隔由这次的自评和提示层级决定。

反馈：今日和专题侧栏显示的是能力原句和「上次没能独立解释队尾淘汰」。专题标题旁没有红色的「未掌握」。

异常：用户当时归错了原理。可以把证据改挂到另一条能力。旧证据保留，新挂接再记一条，不改历史。

成功：失败有具体句子。下一次复查问的是这句，不是「单调队列还记得吗」。

### 4.5 场景 E：算法「状态」与 Agent「状态」

触发：学习 Agent Runtime 的持久化和恢复时，想起算法里的状态。

步骤：

1. 搜索「状态」。结果分域列出，每条带核心陈述。算法一条，Agent 一条。
2. 并排打开。左：对未来决策有影响的历史摘要。右：一次执行在中断后仍能恢复的持久事实。
3. 建立类比关系。边界必填，例如：算法状态可以合并，当且仅当未来决策不变；Agent 状态的恢复不能把副作用再执行一遍。边界为空不能保存。
4. 界面没有「合并这两个对象」。
5. 在 Agent 一侧可以继续对比 Retry、Resume、Replay：三者改变的是失败后做什么，不是状态等价。

反馈：两条对象 ID 不同。类比边的两端都显示同一段边界。合并建议列表不出现这一对。

异常：用户坚持这是同一个结构，而不是同名。保存非类比、非对比的跨领域关系前，再确认一次「这是同一个结构，还是仅仅同名」。默认仍是两个对象。

成功：以后从任一侧重都能走到另一侧，并看见边界。搜索「状态」不会只返回一条。

### 4.6 学习一个新专题

触发：进入还没有正文的专题，或从阶段路径进入下一专题。

步骤：看阶段位置和依赖顺序 → 若有薄弱前置，先看见最多 3 条 → 粘贴或写作 → 处理建议托盘 → 为这个专题确认至少一条能力，或明确标成「先只收集」。

异常：依赖还没写时，不阻止阅读。侧栏不编造前置。

成功：专题有正文。已确认的对象出现在侧栏。未处理的建议在「稍后」，不挡下次打开。

### 4.7 查找

触发：记得结论的一部分，或记得自己做过一个决定。

步骤：搜索框同时查对象名、别名、核心陈述、未解决的疑问、架构决定。例子：「我之前为什么放弃把 Agent Loop 设计成 Workflow？」命中挂在模型「Agent Loop」上的决定记录，正文写明放弃的理由，而不是命中一篇散笔记。

反馈：结果先按对象分组，再列出它所在的专题。同名跨领域并列，不折叠成一条。

异常：只有正文命中、还没有对象时，结果标成「专题里的句子」，并提供「提升为对象」。

成功：从一句记得的话走到对象、专题和相关能力。

### 4.8 主动复习

触发：今日里一条能力到了建议复查日，或用户提前打开它。

步骤：先不展示专题正文。出示能力原句和任务（解释、推导或辨别）。用户作答后自评。失败后再打开原来的表达。完成后写一条证据，重算建议复查日。

异常：用户想先重读。允许，但这条不记为独立完成，记为「先看了材料」。

成功：证据追加。旧证据还在。到期状态变化。没有分数变化。

### 4.9 学新内容时带上前置

触发：打开专题，其对象的前置能力里有「上次失败」或已到期的。

步骤：侧栏列出最多 3 条，每条是能力原句。可以进入该条练习，或留到本次阅读结束。不自动插入整篇旧专题。

成功：新专题的阅读不被队列占满。真正弱的前置被点名。

### 4.10 长期演化

触发：使用数周后，分类方式变了。

步骤：重挂大纲，合并真正重复的对象，拆开误绑的表达，保留证据。核心陈述改了以后，各专题表达标「核心定义已更新」，直到在该表达上确认已读。确认不改正文。

成功：体系变了，身份和历史还在。三个专题引用同一对象时，活跃身份仍然是一行。

## 六、核心页面

桌面优先。原型用同一套布局，屏幕可点击。下面的草图和原型一致。

视觉只强调一件事：推导的顺序。阅读列保持连续。结构挂在旁边，不把正文切成卡片。需要人决定的事项用同一种标记，其余界面保持安静。

### 6.1 每天打开第一眼

今日不是仪表盘。主列是当前体系位置，和上次停住的那句自己的话。


### 6.2 体系工作台

```
顶栏   算法本质训练体系 / 阶段一 / 从决策树到状态空间
       正文  推导  对比  关系          搜索

大纲          推导脊           正文                      身份账本
阶段一        决策树           从决策树到状态             状态等价
  从决策树    状态             连续段落                   概念
  到状态空间  状态等价 ←       表格                       演化自 决策树
阶段二        状态合并         代码                       实现    记忆化搜索
  候选淘汰    DAG              个人句子                   能力
              Memo                                        能判断哪些历史
              Bottom-up                                   影响未来
```

- 大纲是学习编排。顺序按依赖，不按笔记最初写下的时间。例：LC139 已读，状态等价在读，LC140 用来再检验。
- 推导脊是这条论证的阶段，可以和文档标题不同。当前阶段明显标出。
- 正文最大宽度适合长句。表格和代码留在原位。
- 身份账本只列这个专题已经确认的对象。关系动词写出来。点击对象进入对象页。

四个投影共用大纲和账本：

- **正文。** 完整推导。
- **推导。** 只展开脊上的七步，每步一句。用来重建顺序，不替代正文。
- **对比。** 若本专题有对比关系，中列变成矩阵。回溯与 DP 是默认例子。行是解空间、重复子问题、目标、失效条件、代表题。
- **关系。** 中列变成当前专题的局部图。节点是已确认对象，边写类型。超过邻居范围的不画。

变体链从账本里的变体关系进入，也可以在对比投影里切换到 LC131 → LC132。变化条件写在链上：目标从「全部方案」变成「最少分割数」，于是要最优子结构，不再保留所有路径。0/1 背包与完全背包是第二条链：物品能不能重复选，改变了内层循环方向。

### 6.3 粘贴融合

粘贴发生在工作台正文里。保存是同步的。托盘贴在账本上方，不盖住正文。

每条建议一行，包含：它认出来的是什么、预填的关系说明、接受、先不。接受「最优子结构 / 重叠子问题」时，按钮是「建成对比」。没有「合并」按钮。

个人句子的建议写成「挂到已有对象上」。

托盘可以整层收进「稍后」。收起后再读，正文一个字不少。

### 6.4 对象页

以「状态等价」为例。

- 标题、类型、领域、稳定 ID、核心陈述。
- 别名单独列出。最优子结构和重叠子问题不出现在别名里。
- 两份表达：DP 专题的推导；图搜索专题的 visited、LC752、LC773。改其中一份正文，另一份不变。
- 关系列表，类比边把边界原文显示出来。
- 能力列表：原句加最近证据。没有证据就写「还没有证据」。
- 个人理解、疑问、曾经的错误认识，附在对象下，不另开一种知识类型。

从对象可以进入练习，或回到某一份表达所在的专题位置。

### 6.5 重组

从专题标题进入。三个动作并列，各自用一句话说明后果。执行后同一层里显示：对象 ID 未变，证据条数未变，父节点已变。撤销回到执行前的父节点。

### 6.6 练习与返回

练习页先放题面或能力原句，不放算法名称，不放专题正文。提示逐级出现。第 3 级出现后，独立完成不可用，并写明原因。

完成后提供两个回去的入口：回到这条能力所在的原理段落；把刚才的障碍挂到对象上。

回查页使用场景 D 的文案。页面标题是能力原句，不是「复习卡片 12」。

### 6.7 类比并排

两列核心陈述，中间一段边界。Retry、Resume、Replay 放在 Agent 列下方，作为三个方法的对比，不并进「状态」的别名。页上写明：名称相同，这两个对象保持独立。

### 6.8 键盘

- `⌘K` 搜索。
- 工作台里 `[` `]` 切换投影。
- `⌘Enter` 保存正文。
- `⌘Z` 撤销上一条结构命令。
- 练习里 `1` `2` `3` `4` 展开到对应提示级。
- 建议托盘里 `A` 接受当前条，`S` 延后当前条。

按钮都可聚焦。动效只用于展开提示和切换投影，并服从系统的减少动态效果设置。

## 七、知识数据模型

### 7.1 实体

| 实体 | 职责 | 不做什么 |
| --- | --- | --- |
| User | 所有者 | 第一版只有一个用户 |
| Domain | 领域。防止误合并，供搜索分组 | 不是权限边界，不阻止跨领域关系 |
| KnowledgeSystem | 一套学习体系 | 不拥有知识对象 |
| OutlineNode | 体系里的节点 | 节点种类不是知识类型 |
| Document | 节点上的连续正文 | 不是知识身份 |
| Block | 文档中的块索引 | 不把每个块都变成对象 |
| KnowledgeObject | L1 身份 | 不保存某个专题的长推导 |
| Expression | L2。对象在某文档中的块绑定 | 不复制一套平行正文 |
| Annotation | L3，以及疑问、错误认识、突破、架构决定 | 不升格成十几种实体 |
| Relation | 有类型的边 | 不表示「相关」 |
| Capability | 能力目标。最小学习单元 | 不等于对象，也不等于某次任务文案 |
| Evidence | 一次不可变的学习事实 | 不保存当前分数 |
| ReviewState | 由证据重放的调度缓存 | 不是权威历史，可整表重算 |
| Source | 一次粘贴或导入 | 不代替正文 |
| Revision | 结构命令日志 | 不记录每一个按键 |

不单建的候选：

- ContentFragment 并入 Annotation。标记可以以后再提升成对象。
- Practice 不单独成题库。任务文案、提示级和参考说明放在 Capability 上，用户可改。
- 认知笔记不单建，用 Annotation 的 kind。
- 条件不是对象类型。条件写在关系的 `condition` 或 `what_changed` 上。一个条件日后重要到像「最优子结构」，再提升为原理对象。
- 术语不是对象类型。术语是别名。
- 技术落在方法或模型上。
- **架构决定不新开对象类型。** 它是挂在模型上的 Annotation，kind 为 `decision`，正文包含选择、放弃的方案和理由。搜索「为什么放弃把 Agent Loop 设计成 Workflow」命中的是这条记录。若使用后发现决定需要自己的关系（例如「取代了哪个模型」），再考虑第六种对象类型。这是建议，确认时可以改。

### 7.2 对象类型

五种：

| type | 含义 | 例子 |
| --- | --- | --- |
| concept | 概念 | 状态等价；状态 |
| principle | 原理 | 最优子结构；重叠子问题；候选支配 |
| method | 方法 | 记忆化搜索；单调队列；Retry；Resume；Replay |
| model | 一种看法的框架 | 决策树；状态 DAG；Agent Loop；Agent Workflow |
| problem | 问题实例 | LC140；LC862；LC131；LC132 |

反例是关系或一条 Annotation，不是类型。

名称在同一用户、同一领域内唯一。规范化：NFKC、去首尾空白、折叠连续空白、英文小写。跨领域同名允许，因为唯一键包含领域。别名在同一用户内不能指向两个活跃对象。

### 7.3 关系词表

| type | 含义 | 必填 | 例子 |
| --- | --- | --- | --- |
| prerequisite | from 是 to 的前置 | 无 | 决策树 → 状态等价 |
| part_of | from 是 to 的一部分 | 无 | 状态转移 part_of 状态 DAG |
| evolves_from | from 由 to 演化而来 | what_changed | 状态等价 ← 决策树，因为重复子问题被合并 |
| specializes | from 是 to 的特例 | 无 | 0/1 背包 → 背包 |
| contrasts | 无向，本质区别 | distinction | 回溯 ↔ DP；最优子结构 ↔ 重叠子问题 |
| variant | from 是 to 的变体 | what_changed | LC132 → LC131，目标改成最少分割数 |
| applies | from 用于 to | 无，建议写 condition | 状态等价 → LC139 |
| implements | from 实现 to | 无 | 记忆化搜索 → 状态等价 |
| fails_when | from 在该条件下失效 | condition | 贪心在局部最优推不出全局最优时失效 |
| counterexample | from 是 to 的反例 | 无 | 某次错误的状态合并 → 状态等价 |
| analogous | 无向类比 | boundary | 算法「状态」↔ Agent「状态」 |

`analogous` 没有边界就拒绝保存，并且不进入「可能重复」列表。跨领域又不是类比或对比的关系，保存前多确认一次。

无向类型的唯一键用排序后的两端。禁止自环。

### 7.4 一个身份，多份表达

`状态等价` 一行。领域是算法。核心陈述例：「若两个历史对未来的可选决策和目标值没有区别，它们就是同一状态。」

- DP 专题的表达：角色 `derivation`，块覆盖决策树合并、DAG、Memo、LC139、LC140、自顶向下代码。
- 图搜索专题的表达：角色 `derivation`，块覆盖 visited、LC752、LC773、去重为什么是对的。

两段正文互不覆盖。核心陈述版本增加时，两份表达都显示「核心定义已更新」。确认只更新该表达看过的版本号。

引用与复制：

- 转写引用是活的，指向块 ID。
- 复制并断开是新块，保留 `derived_from_block_id`。
- 没有「把整份专题同步成另一份」的操作。

块 ID 是稳定 UUID。引文加哈希可以标记「这段文字已经改过」，不能代替块 ID。块在文档里的序号只表示阅读位置。

### 7.5 关键字段与约束

标识用 UUID。业务表含 `user_id`、`created_at`、`updated_at`。删除默认软删除。

**OutlineNode.** `system_id, parent_id, position, kind, title, document_id`。`kind` ∈ `stage | chapter | topic | note`。同一父节点下 position 唯一。禁止环。专题必须有文档。父节点的 kind 不约束子节点，重构时章节下仍可以放章节。

**Document.** `schema_version, content_json, plain_text, saved_at`。`content_json` 只接受 schema 白名单。每次成功保存把上一份 JSON 留在文档修订里，每文档保留最近 30 次。

**BlockIndex.** `block_id, document_id, parent_block_id, position, type, text_preview`。保存文档时重建。块 ID 发放后不复用。外部粘贴带来的 ID 全部换新。

**KnowledgeObject.** `type, domain_id, canonical_name, normalized_name, aliases, core_statement, core_version, status`。`status` ∈ `active | merged`。合并后读取旧 ID 跳到保留 ID。`core_statement` 可空；为空时不能作为练习的对照材料。

**Expression.** `object_id, document_id, block_ids, role, core_version_seen`。`role` ∈ `definition | derivation | example | code | contrast | personal | other`。块必须属于该文档。一个块可以属于多条表达。保存文档时若删除了仍被表达引用的块，拒绝保存，除非请求明确列出要解除的表达。

**Annotation.** `target_type, target_id, kind, body, resolved_at`。`target_type` ∈ `object | block | capability | relation`。`kind` ∈ `understanding | question | misconception | breakthrough | counterexample | unresolved | decision`。未解疑问查询 `question` 与 `unresolved` 且未解决的行。`decision` 的 body 约定含放弃的方案和理由，不必再拆表。

**Relation.** `from_id, to_id, type, distinction, what_changed, condition, boundary, note, status, origin`。`status` ∈ `suggested | accepted | deferred | rejected`。`origin` ∈ `user | rule | model`。延后和拒绝都留下，避免同一条建议反复出现。只有 `accepted` 出现在账本和局部图里。

**Capability.** `statement, kind, prompt, hints, reference_note, primary_object_id`。`kind` ∈ `explain | derive | discriminate | vary | counter | implement | transfer | tradeoff`。与对象多对多。`transfer` 在其主对象所关联的非迁移能力至少有一次独立通过之前，练习接口拒绝。

能力 kind 与训练形式：

| kind | 训练在问什么 | 例子 |
| --- | --- | --- |
| explain | 独立解释 | 解释状态等价的定义 |
| derive | 重建推导 | 从决策树推到 Memo |
| discriminate | 方法辨别 | 回溯和 DP 差在哪个条件 |
| vary | 条件变化 | 0/1 背包改成完全背包，循环为什么换方向 |
| counter | 反例 | 这种状态合并为什么是错的 |
| implement | 代码或操作 | 写出 LC140 的记忆化 |
| transfer | 迁到还没见过的条件 | 在新题里找出可压缩的状态 |
| tradeoff | 架构权衡 | Agent Loop 为什么不做成 Workflow |

第一版所有 kind 共用同一个练习骨架：原句、作答区、分级提示、自评、障碍。提示文案按 kind 不同。不每种做一套完全不同的界面，也不把它们收成同一句「回忆一下」。

**Evidence.** `capability_id, mode, hint_level, rating, obstacle, body, created_at`。`mode` ∈ `recall | derive | practice | review | self_report_failure | reread`。`rating` ∈ `fail | partial | with_hint | independent | saw_material`。没有更新接口。写错了再记一条。`hint_level >= 3` 时拒绝 `independent`。

**ReviewState.** 每个能力一行。缓存 stability、difficulty、due_at、reps、lapses。权威是 Evidence。

**Source.** `document_id, kind, locator, plain_fallback, content_hash, captured_at`。`kind` ∈ `paste | import | manual`。纯文本副本单次上限 1 MB。

**Revision.** `command, payload, inverse, undone_at`。命令包括 `reparent_node, move_blocks, transclude_blocks, copy_blocks, merge_objects, split_expression, bind_expression, trash_node, restore_node`。未撤销命令保留最近 50 条。更早的恢复靠导出包。

### 7.6 生命周期

**创建对象。** 来自建议被接受，或从选中文字「提升」。必须有名称、类型、领域。不自动写关系，不自动写能力。

**复用。** 把块加入已有表达，或接受「这就是已有对象」。不复制核心陈述。

**合并。** 只用于同一领域里确认重复的对象。保留一个 ID，表达、关系、能力链接并过去。证据仍挂在原能力上，条数不增。类比关系的两端不能走合并。

**拆分。** 把一部分表达改绑到新对象。旧证据留在旧能力上，不自动复制。

**删除。** 仍有已接受的关系或表达时拒绝，返回计数。用户选择「解除并删除」后软删除。永久删除前要再输入名称。

### 7.7 一致性

- 所有查询带 `user_id`。
- 表达的块必须属于该文档。
- 别名全局唯一到一个活跃对象。
- 类比边界非空。
- 提示层级和「独立完成」互相约束。
- 迁移任务依赖源能力的独立通过记录。
- 局部图和矩阵只读已接受的关系，不写第二份数据。

## 八、学习训练与复习机制

### 8.1 最小学习单元

最小单元是 Capability：一句可观察的能力。

知识对象「状态等价」可以对应多条能力：能解释定义；能判断哪些历史影响未来；能识别重复子问题；能独立设计 Memo 状态；能解释某种状态合并为什么错；能在陌生题里找到可压缩的状态。

「队列只保留对未来有贡献的下标」是另一条能力，主要对象是原理「候选支配」，不是整章「单调队列」。

一条能力可以横跨多个对象。例如辨别回溯与 DP，同时挂这两个模型。

### 8.2 任务从哪里来

- 用户在对象或专题上写一句话，选择 kind。
- 失败现场用障碍原文生成一条，用户改过句子再保存。
- 对比关系和变体关系可以生成辨别或条件变化任务，文案使用关系上的 `distinction` 或 `what_changed`。用户不接受就不创建。
- 不从全文自动生成选择题。

### 8.3 分级提示

每条能力最多 4 级提示，默认为空时使用 kind 的通用提示。

LC140 的四级见场景 C。第 3 级揭示状态定义，因此达到第 3 级就不能记独立完成。这个阈值写在能力上，默认 3，用户可改。

已有独立通过记录的能力，打开练习时不展开任何提示。

### 8.4 反馈

系统不判断开放答案对不对。它做的是：锁住提示、记下层级、保存自评和障碍原文、在失败后给出原来的表达链接。

代码实践第一版也不自动跑测试。用户自己标明是否独立写出。自动运行用例留到有真实使用之后再决定，而且只可能覆盖 `implement`，不覆盖解释和推导。

### 8.5 什么时候复习，间隔怎么变

三种触发同时存在：

1. **时间。** ReviewState 的 `due_at` 到来，出现在今日。提前复习始终允许。
2. **结构变化。** 核心陈述版本更新，相关能力在今日标成「定义已改，建议重看」，不直接当成失败。
3. **再次失败。** 失败证据把该能力排进下一次今日，即使原定复查日还没到。

调度使用 FSRS 的默认参数，封装成纯函数：输入上一次状态和这次 rating，输出下一次状态和 `due_at`。`independent` 按成功回忆，`with_hint` 和 `partial` 按较难，`fail` 按遗忘，`saw_material` 不推进成功计数。它只决定何时再问。界面始终同时显示最近一次证据的原话。

重读不是证据里的成功。被动打开专题不写 Evidence。

### 8.6 交错

默认关闭。仅当两个对象之间有已接受的 `contrasts` 或 `variant`，并且两边各自至少有一次独立通过之后，才允许一次辨别练习把它们放在一起。新专题学习期间不插入交错。

第一版把关系写下来，并在对比、变体投影里使用。专门的交错会话放在下一阶段。数据已经够，不需要新的知识模型。

### 8.7 迁移

`transfer` 任务在源能力独立通过之前不可用。通过 LC139 的记录不会自动变成「能做新 DP」。迁移题由用户指定，系统只检查门槛并保存证据。

具体 → 抽象 → 再具体，用编排表达，不另建路径实体。例：大纲顺序是 LC139，然后状态等价，然后 LC140。LC140 的能力 kind 可以是 `transfer` 或 `implement`，由用户定。

### 8.8 能力在界面上的说法

只使用证据语言：

- 还没有证据
- 上次独立完成
- 上次用了提示
- 上次失败，后接障碍原文
- 定义已改，尚未重看
- 到了建议复查日

不出现掌握百分比、等级和连续打卡。

## 九、AI 能力设计

AI 是知识工程助手。它不是第二套聊天产品，也不是会自动改体系的代理。

### 9.1 哪些用规则，哪些用模型

规则，保存后立即运行，不依赖网络：

- 标题、加粗文本、别名表命中已有对象。
- 个人句子的启发：位于用户标记过的「个人思考」段落，或第一人称判断句，且句中含有已有对象名。建议是挂到该对象，不是新建。
- 两个已有原理在同一段出现，且没有互为别名。建议对比，禁止建议合并。
- 跨领域同名。建议类比，禁止建议合并。

模型，仅当用户配置了密钥，并且规则没有把托盘填满时，对本次粘贴补关系建议：

- 输入：这次粘贴的纯文本、当前专题标题、最多 30 个候选对象的名称与核心陈述。候选来自规则命中和当前专题已有对象，不是全库。
- 输出：最多补足到 5 条。每条包含类型、两端名称、预填的 distinction / what_changed / condition / boundary、它引用的原文片段。
- 输出进同一个托盘，`origin = model`，状态 `suggested`。不直接写 `accepted`。

不交给模型的事：

- 保存正文、发块 ID、改大纲。
- 判断练习答案。
- 生成掌握分数。
- 在没有人确认的情况下创建对象或关系。

### 9.2 触发与确认

触发只有两个：粘贴或导入保存之后；用户在选中文字上选择「识别」。打开应用、每次按键、每次滚动都不触发。

确认是逐条的：接受、先不、忽略。接受前可以改预填说明。忽略写入 `rejected`，同一片段不再建议同一条。先不写入 `deferred`，今日能看见「还有几条稍后处理」，不弹窗。

一次粘贴超过 5 条候选时，只展示规则优先级最高的 5 条，其余留在稍后，不展开成向导。

### 9.3 失败、成本、安全

- 模型超时、拒绝或返回无法解析的结构：托盘保留规则结果，并写「模型建议这次没有生成」。手工新增关系可用。
- 没有密钥：产品完整可用，只是没有模型那几条。
- 单次输入限制在本次正文和候选名单。不上传整个知识库，不上传其他专题正文。
- 发送前，托盘能展开「这次会送出的范围」。
- 密钥放在服务端。日志不记正文。
- 粘贴的 HTML 去掉脚本、事件属性和不安全 URL。渲染走 schema，不把原始 HTML 写入页面。

成本控制：一次保存最多一次模型调用。用户可以关掉模型建议，规则仍运行。

### 9.4 来源

每段内容能区分：粘贴来的原文、模型建议、用户自己的理解、已经在练习里独立通过的解释、尚未解决的疑问。

模型建议在被接受之前不是事实。接受后 `origin` 仍保留，对象页可以看见这条关系当初是模型提出的。

## 十一、MVP

MVP 要能每天走完这条闭环：

**建立体系 → 粘贴一段真实推导 → 确认对象和关系 → 用正文、推导、对比或变体再看一遍 → 做一次练习或登记一次失败 → 留下证据 → 之后在今日里再碰到这条能力。**

深度限定：

- 体系就是大纲加每节点一份文档。不做第二套「学习路径」数据库。
- 建议托盘在。规则建议在。模型建议在同一托盘里，没有密钥就缺那一部分，不缺手工路径。
- 八种能力 kind 共用一个练习骨架，提示文案不同。
- 局部关系图只画当前专题已接受的对象。对比和变体是表和链，不是新编辑器。
- 交错会话不做。关系先记下。
- 账户只有一个，注册关闭。

页面：

1. 今日
2. 体系工作台，含四种投影、托盘、重组层
3. 对象页，含类比并排
4. 练习页，含失败回查这一种进入方式

原型 `docs/prototype/index.html` 用真实例子走这些页面。它是确认用的界面，不是实现。

## 十二、技术架构

工程形态沿用已经确认的实现路线。产品对象、关系、练习和界面不从既有学习应用搬。仓库独立，不依赖外部应用的包。

### 12.1 栈

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 仓库 | pnpm workspace，Node ≥ 22，TypeScript 5.9，ESM | 已确认。TypeScript 不用 7，避免把夹具押在另一套编译器上 |
| Web | Vite 6、React 19、React Router 7、`@rabjs/react`、普通 CSS | 已确认。工作台状态适合集中在 service。不用 Next.js，不用 Tailwind |
| API | Fastify 5。路由做认证和 Zod，事务在 service | 一个进程够用 |
| 数据 | PostgreSQL、Drizzle、`pg` | 关系和文档 JSONB 都在这里。不用 Neo4j，不用 SQLite |
| 文档 | 自有 `packages/doc-schema` 与 `packages/markdown` | 短 schema。块上稳定 UUID。不引用外部应用的 schema，避免焊上不属于本产品的节点 |
| 调度 | `ts-fsrs`，纯函数，固定时钟可测 | 只产出复查日。不使用三档 SM-2 作为本产品的算法 |
| 搜索 | PostgreSQL `pg_trgm` 与 `ILIKE` | 个人规模够用。不部署独立检索引擎和向量库 |
| 图 | 自绘 SVG，节点上限 50 | 局部投影。不引入图布局框架 |
| 登录 | argon2，HttpOnly Cookie | 注册关闭。迁移时种一个用户 |
| 测试 | Vitest 3 | 逻辑不连库。粘贴是纯函数夹具 |

进程：浏览器里的 SPA，Cookie 调 Fastify，Fastify 调 PostgreSQL。图片放本地磁盘。没有 worker，没有对象存储，没有微服务。模型调用若变慢，再加一张 Postgres 作业表，不先引入队列集群。

目录：

```
apps/server      Fastify、Drizzle、认证、事务
apps/web         页面
packages/dto     Zod 契约
packages/doc-schema
packages/markdown
```

### 12.2 文档与粘贴

权威格式是带 `schemaVersion` 的 ProseMirror JSON。块节点有 `id`。

schema 只保留：标题、段落、列表、引用、表格、代码高亮、KaTeX、Mermaid、图片、对象引用。Mermaid 渲染失败仍保留源码。

粘贴规则：HTML 能保住表格和代码时走 HTML。纯文本明显含有标题、围栏代码、GFM 表格或 `$$` 时走 Markdown。富 HTML 里只有加粗时，仍走 HTML。解析是纯函数。服务端用同一 schema 再校验一次。

这一规则和夹具已经在仓库里，用来保住表格、JS 缩进、公式和脚本剥离。那是管道，不是产品界面。确认本 PRD 之后，把它接到专题文档上，而不是把夹具页扩展成应用。

图片限 PNG、JPEG、WebP、GIF，单文件 10 MB。不接受 SVG 上传。

导出包是 JSON 加文件。Markdown 由 JSON 导出。对象引用写成 `[[object:<uuid>|显示名]]`，导入按 ID 还原。

### 12.3 安全、备份、部署

- 查询都带 `user_id`。
- Cookie：HttpOnly、`SameSite=Lax`，生产环境 `Secure`。
- 页面不把粘贴 HTML 直接写入 `innerHTML`。
- 结构命令有逆操作。正文保留最近 30 次。用户另可下载导出包。机器级恢复用 `pg_dump`。
- 本地：Docker Compose 里的 PostgreSQL，`pnpm dev` 起服务端和 Web。
- 生产：一个服务端镜像，内含构建后的 SPA，前面用反向代理终止 HTTPS。迁移在启动前单独执行。

### 12.4 风险

| 风险 | 处理 |
| --- | --- |
| 粘贴损坏表格或代码 | 夹具失败就先修管道 |
| 把对象做成挂在专题上的行 | 评审对照第七节。跨专题复用会直接失败 |
| 用块序号当引用 | 表达只存 UUID |
| 模型建议写进正式关系 | 接口只允许人把 `suggested` 改成 `accepted` |
| 局部图膨胀成全库图 | 节点上限 50，只取当前专题 |
| 复查日被看成能力分数 | 界面同时显示证据原话 |
| 把夹具页当成产品 | 产品界面按第六节和原型做 |

## 十三、分阶段路线

确认后再写。每个阶段结束时应用可运行，迁移可重复，该阶段的测试通过。不用假数据冒充还没接入的模型。

已有的粘贴夹具算阶段 0 的管道，不算产品交付。

### 阶段 1：体系与正文

- 交付：登录、体系、大纲、文档保存与再打开、粘贴进专题、30 次保存点、推导脊。
- 数据：User、System、OutlineNode、Document、BlockIndex、DocumentRevision、Source。
- 页面：工作台的大纲、脊、正文。
- 验收：刷新后表、代码、公式仍在。拖拽重挂后位置仍在。脊的当前阶段可以指定，且不另存一份正文。
- 不做：对象、练习。

### 阶段 2：身份、关系、建议托盘

- 交付：五种对象、表达、关系、别名、账本、规则建议、手工关系。模型调用按第九节接上，没有密钥则跳过。
- 数据：Domain、Object、Expression、Relation、Annotation。
- 验收：第十四节里身份、表达、类比、建议逐条接受的条款。
- 不做：练习。

### 阶段 3：重组

- 交付：移动、转写引用、复制断开、合并、软删除、撤销、导出。
- 数据：Revision。
- 验收：场景 B。对象 ID 和证据条数在移动前后一致。
- 不做：可视化的完整历史浏览器。

### 阶段 4：学习闭环

- 交付：能力、练习页、四级提示、证据、调度重放、今日、薄弱前置、失败登记。
- 数据：Capability、Evidence、ReviewState。
- 验收：场景 C 和 D。用一条固定证据序列断言复查日。不连接外部模型来判分。
- 不做：交错会话、自动评分、个人权重。

### 阶段 5：投影补齐

- 交付：对比矩阵、变体链、局部关系图、对象页的双表达与类比并排、搜索疑问和架构决定。
- 数据：不新增知识实体。图和矩阵是查询。
- 验收：回溯 / DP 矩阵、LC131 → LC132、算法状态 / Agent 状态与场景 E 的条款。
- 不做：两跳以上的探索、全库图。

阶段 5 完成，MVP 才算完成。只做完阶段 1 到 4，产品仍缺原始说明里的视图。

阶段 2 的模型调用若阻塞正文交付，可以在阶段 2 先交付规则托盘，在阶段 5 之前补上同一托盘的模型来源。缺少的是来源，不是另一套交互。

## 十四、验收标准

用测试或一次可重复的手工步骤判定。

### 14.1 身份与表达

1. 创建「状态等价」。三个专题各绑一条表达。该规范名的活跃对象是 1 行。三个专题解析到同一个 ID。
2. 三份正文可以不同。改一份，另外两份的正文哈希不变。
3. 修改核心陈述。三份表达都显示待确认。确认一份只改该表达的已读版本，正文不变。
4. 另一个领域也可以有对象「状态」，ID 不同。搜索同时给出领域和核心陈述。
5. 类比不填边界，接口拒绝。填入后两端都显示这段边界。合并列表不包含这一对。
6. 「最优子结构」和「重叠子问题」不能保存为彼此的别名。建议托盘给出的是对比。
7. 个人句子接受后，是对象上的 Annotation，对象行数不增加。

### 14.2 重构

1. 移动专题后，对象 ID、已接受关系、证据条数不变，父节点改变。
2. 转写引用后，两处读到同一块 ID。改一块，另一处相同。
3. 复制断开后，块 ID 不同，`derived_from_block_id` 指向源。改新块不影响源。
4. 撤销移动后，父节点恢复，证据条数仍不变。
5. 删除仍被表达引用的对象，接口拒绝并返回计数。

### 14.3 内容保真

1. 夹具中的表格是 2 行 3 列。
2. JavaScript 代码的语言、缩进和 `<` 保留。
3. 行内公式和显示公式在导出 Markdown 再导入后，源码不变。
4. `<script>` 和事件属性不进文档。个人句子留在文档里。
5. Mermaid 源码留在独立块里。渲染失败时源码仍在。

### 14.4 建议托盘

1. 一条粘贴的建议可以单独接受、延后、忽略。
2. 忽略后再粘贴同一片段，不重复建议同一关系。
3. 模型不可用时，规则命中的对象建议仍在，手工新建关系可用，正文已保存。
4. 模型输出不能直接成为 `accepted` 关系。
5. 一次展示不超过 5 条。

### 14.5 学习证据

1. 完成一次练习后，证据挂在指定能力上，条数加一。专题上没有掌握分数字段。
2. 提示层级 ≥ 3 时，提交独立完成被拒绝。
3. LC862 的失败证据可以只挂在「队列只保留对未来有贡献的下标」上。同专题其他能力的最近证据不变。
4. 被动打开专题不新增证据。
5. 删除 ReviewState 后重放 Evidence，得到同一个 `due_at`。
6. 源能力没有独立通过时，创建或开始 `transfer` 练习被拒绝。

### 14.6 投影

1. 对比矩阵的单元格来自已接受的 `contrasts` 关系及两端对象，没有单独的矩阵表。
2. 变体链的顺序和「变了什么」来自 `variant` 关系。
3. 局部图的节点集合等于当前专题表达所指向的对象，加上它们之间已接受的边。拒绝画上专题外的第二跳。
4. 推导脊的阶段顺序存在专题的脊设置里。它不复制正文块。

### 14.7 恢复

1. 连续撤销 50 条以内的结构命令，大纲回到那些命令之前。
2. 导出再导入后，对象 ID、表达的块引用、证据条数保留。
3. 永久删除需要再输入对象名称。删除前的导出包仍能导回。

## 十五、学习效果与产品指标

不把 DAU、笔记篇数、节点数当作成果。

试用期就记录：

- 从粘贴到处理完托盘的时间，以及被忽略的建议比例。比例长期接近 100%，说明建议在添乱。
- 一次粘贴里，接受的「挂到已有对象」次数与「新建对象」次数。前者应随库变大而变多。
- 重构次数，以及重构后仍能打开的旧证据比例。目标是不丢。
- 每周打开对比、变体、对象多表达的次数。长期为零，说明这些投影没有进入真实学习。
- 练习里独立完成、用了提示、失败的次数。分开记，不合成一个分数。
- 失败证据里，障碍原文非空的比例。
- 每周整理结构的时间与阅读、练习时间的大致比例。整理持续高于学习，就减少托盘和字段，而不是加仪表盘。

两个月以上的证据再看：

- 同一能力在间隔后的独立完成是否比上次更少依赖提示。
- 用户标记为迁移的题目，在源能力独立通过之后的完成情况。
- 跨领域类比被打开的次数，以及其中边界被改写的次数。边界经常被改，说明类比写早了，不是失败本身。

不采用：掌握度、知识完整度、连续打卡、节点增长率、模型建议的自动接受率。

## 十六、确认前的假设

下面几条会改变数据模型。原型和本文按它们绘制。不同意就先改这里，再开发。

1. 对象类型就是概念、原理、方法、模型、问题。架构决定先做模型上的 `decision` 注解。
2. 关系就是第七节的十一种。类比必须有边界，并且不提供合并。
3. 最小学习单元是能力原句。没有掌握度百分比。
4. 开放回答由用户自评。提示到第 3 级不能记为独立完成。
5. 建议托盘属于 MVP。规则一定有。模型是同一托盘的第二个来源，没有密钥时产品仍完整。
6. 正文、推导脊、对比、变体、局部关系、能力清单属于 MVP。全库图不做。
7. 交错会话不做进 MVP。对比和变体关系要做进 MVP。
8. 工程栈维持已确认的那一版。产品界面按第六节实现，不沿用任何既有学习应用的信息架构。
9. 不导入 LeetCode 题库。
10. 已写好的粘贴解析器只作为管道保留。确认前不继续加应用功能。

确认时直接指出要改的假设、旅程或原型屏幕即可。
