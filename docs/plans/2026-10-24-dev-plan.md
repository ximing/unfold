# Unfold 分阶段开发计划

日期：2026-10-24。
配套文档：`docs/prd/2026-10-24-unfold-prd.md`（产品语义唯一依据）、`docs/tech/2026-10-24-tech-design.md`（技术实现唯一依据，下称技术方案）、`docs/prototype/index.html`（交互与视觉唯一参照，浏览器直接打开可点击）。

执行者：新接手的开发 Agent。**开始前必读三份配套文档**，然后按阶段顺序执行，不跳阶段。

---

## 总则：每个阶段「完成」的定义（DoD)

一个阶段只有同时满足以下全部条件才算完成：

1. `pnpm test` 全绿（Vitest，含本阶段新增的纯函数与集成测试）。
2. `pnpm typecheck` 与 `pnpm lint` 零错误。
3. 数据库迁移可重复执行（`migrate` 连续跑两次不出错）。
4. **浏览器验收（金标准）**：启动 `pnpm dev`，用 csi skill 驱动真实 Chrome，逐项走完本阶段「浏览器验收」清单并全部通过。自动化测试绿但浏览器点不通，阶段不算完成。
5. 不用模拟数据冒充未接入的能力：模型/向量未接入时，界面必须呈现降级态（PRD 与技术方案里写了降级行为），而不是写死假结果。
6. 每个阶段结束是可运行的应用：已交付功能在浏览器里真实可用。

csi 验收的通用动作：`pnpm dev` 后访问 `http://localhost:5173`，用 csi 导航、点击、读页面文本、截图。每阶段清单给出具体步骤与预期可见内容。

## 阶段 0：环境与骨架（1 个交付：能登录的空壳）

**目标**：仓库可开发、可测试、可部署形态确立；外部依赖全部连通验证。

任务：

1. 建库：在 222.128.65.91:25432 上 `CREATE DATABASE unfold_dev; CREATE DATABASE unfold_prod;`(技术方案 3.2)。
2. 部署 Qdrant（技术方案 3.3)；验证 Meilisearch 三把 key 可用（`/health` 免 key，其余需 Bearer)。
3. 根级补 `pnpm lint`(ESLint 9 flat config);`.gitignore` 确认含 `.env*`；提交 `apps/server/.env.example`。
4. 新建 `apps/server`:Fastify 5 + Drizzle + 迁移工具链；`users` 表迁移 + 种子用户；argon2 登录/登出/会话 Cookie。
5. 新建 `packages/dto`(Zod 契约骨架）；改造 `apps/web` 为 React Router 7 + `@rabjs/react` 骨架，`/login` 与 `/today` 占位页；Vite proxy `/api` → :3000。
6. 冒烟接口 `GET /api/today` 返回空聚合（真实库查询，不是写死）。

测试：

- 纯函数：名称规范化（NFKC/折叠空白/小写）单测。
- 集成：登录成功/失败、未认证 401、Cookie 属性（HttpOnly/SameSite)。
- 连通性测试脚本（可用 Vitest 跑，标记为 `integration`)：能连 `unfold_dev`、Meili 带 search key 查空索引不报错、Qdrant 集合可创建。

浏览器验收（csi):

1. 打开 `http://localhost:5173` → 重定向到 `/login`。
2. 错误密码 → 页面出现错误提示；正确密码 → 进入 `/today`（空态文案）。
3. 刷新页面 → 仍在 `/today`（会话保持）;「登出」→ 回到 `/login`。

明确不做：任何业务实体、编辑器。

## 阶段 1：点与块（PRD 阶段 1)

**目标**：点（KnowledgeObject）+ 块文档 + 粘贴保真 + 游离列表。这是产品主体的地基。

任务：

1. 迁移：`domains`、`knowledge_objects`、`documents`、`document_revisions`、`block_index`、`sources`（技术方案 §4)。
2. 块类型注册表：基础块 + 学习块（`derivation_steps`、`tiered_hints`、`personal_note`、`question`、`counterexample`、`decision`)+ `object_ref`/`collection_ref` 引用块；每种注册 `parsePaste/toMarkdown/searchableText`。
3. 接入既有粘贴管道（`packages/doc-schema` 夹具保持绿）到 `POST /api/objects/:id/paste`。
4. 焦点页（`/o/:id`)：内容投影完整实现——核心陈述卡、块渲染（块 hover 显示类型标记，对齐原型）、Tiptap 编辑、⌘Enter 保存、30 保存点。
5. 左栏：领域 → 合集（暂无，显示空）→ 游离点数；`/free/:domain` 游离点列表页。
6. 建点流程：一句话核心陈述 + 类型 + 领域，即可保存（种子态）；种子空态文案对齐原型。

测试：

- 纯函数：粘贴夹具全绿（表格行列、JS 缩进、公式、脚本剥离、Mermaid 源码保留）；块类型注册表完整性（每种类型三件套存在）。
- 集成：建点唯一键（同域重名拒绝、跨域同名允许）；文档保存生成保存点且只留 30 份；删除仍被 `object_ref` 引用的点被拒绝并返回计数；块 ID 不复用（粘贴外部 ID 全换新）。

浏览器验收（csi):

1. 登录 → 今日页点「新建点」→ 只填名称/类型/核心陈述 → 保存成功，左栏该领域游离数 +1。
2. 打开该点 → 从剪贴板粘贴原型 `docs/prototype/index.html` 中「状态等价」演示用表格+代码 → 表格行列正确、代码缩进保留。
3. 写一段话 + 一个疑问块 + 一个折叠提示块 → ⌘Enter 保存 → 刷新 → 内容与折叠态原样。
4. 游离列表页能看到该点，点击回到焦点页。

明确不做：扇区、关系、合集、搜索（浏览器搜索框可以是禁用态或缺席，不得写死假结果）。

## 阶段 2：扇形、链与混合搜索（PRD 阶段 2，搜索栈提前到此阶段）

**目标**：关系词表 + 四向扇区 + 链投影 + 对比并排 + 生产级搜索。搜索提前是因为 Qdrant/Meili 已就绪，早接入早暴露问题。

任务：

1. 迁移：`relations`、`annotations`。
2. 关系 service：十一种词表、必填字段校验（`analogous` 边界非空等）、无向唯一键、禁自环、状态机（suggested→accepted/deferred/rejected)。
3. 扇区面板：焦点页右栏，来历/去向/对照/变化四区，边上说明，点击转移焦点；「发起新连接」表单（方向 → 类型词表受方向约束 → 目标点 → 必填说明）。
4. 链投影 `GET /api/objects/:id/graph|chain`：纯查询；链边文逐字取关系 `what_changed`；SVG 坐标纯函数。
5. 对比并排投影（含类比边界布局，无合并入口）。
6. `packages/search`：索引管线（含 `index_outbox` 重试表）、RRF 融合、精排接入、降级矩阵（技术方案 §6);`GET /api/search`；搜索面板 UI（按点分组、同名跨域并列、合集里的句子标「可提升」)。
7. DashScope embedding/text-embedding-v4 + gte-rerank 接入（key 缺失走降级）。

测试：

- 纯函数：RRF 融合夹具（两个召回序列 → 固定融合顺序）；图/链坐标；类比边界校验；跨域非类比关系二次确认标志。
- 集成：关系状态机；忽略后再建议同一片段不重复出现；搜索端到端（索引两个点 → 关键词命中 Meili 路径；停掉 Qdrant 容器 → 结果仍返回且标注降级）。

浏览器验收（csi):

1. 在「状态等价」点发起连接：演化自「决策树」，填条件变化 → 扇区「来历」立即出现该条。
2. 切「链」投影 → 链上可见两点与边文；切「图」投影（本阶段可先做列表式扇区，图可 P1，但若做则节点点击换焦点）。
3. 搜索「状态」→ 结果按点分组，算法/Agent 两条同名并列；搜索「Workflow」→ 命中挂在 Agent Loop 上的决定。
4. 停 Qdrant(`docker stop qdrant`)→ 再搜索 → 结果仍在且页面有降级提示；恢复容器。

明确不做：建议托盘（手工连接先行）、合集、练习、图投影若来不及移 P1（PRD 已允许）。

## 阶段 3：建议托盘与归位（PRD 阶段 3)

**目标**：粘贴后的连接建议（规则必有、模型可缺）+ 合集编排 + 结构命令撤销 + 导出。

任务：

1. 迁移：`collections`、`revisions`、`index_outbox`（若阶段 2 未建）。
2. 建议托盘：规则建议四条（命中已有点/个人句转 personal_note/两原理对比/跨域同名类比）；模型建议（qwen-plus,Zod 校验输出，最多补足 5 条）；逐条接受/延后/忽略；整层稍后；忽略后同片段不重提。
3. 合集：CRUD + 文档 + `object_ref` 引用块 + 拖拽排序 + 嵌套一层；「归位」面板（编入/移出/新建并编入）;`revisions` 记录全部结构命令，⌘Z / 按钮撤销。
4. 导出包 JSON + Markdown 派生。
5. 今日页完整版：当前点、到期能力（本阶段可为空）、游离数、未处理建议数、未解疑问聚合。

测试：

- 纯函数：四条规则建议的夹具（含「最优子结构×重叠子问题只建议对比不建议合并」);Markdown 导出往返。
- 集成：撤销 50 条内连续恢复；导出→导入后 ID 与引用保留；合集嵌套超一层被拒绝；删除仍被合集引用的点返回计数。

浏览器验收（csi):

1. 在「状态等价」粘贴 GPT 风格内容 → 托盘出现建议 → 逐条接受两条、延后一条、忽略一条 → 扇区/链同步变化，延后的收进「稍后」。
2. 新建合集「状态等价与状态空间压缩」→ 把 3 个点编入 → 合集页引用块可点击进点 → 拖拽改顺序 → 刷新保持。
3. ⌘Z 撤销「编入」→ 合集引用消失，点回到游离。
4. 导出 → 下载 JSON 包；清空该点（软删）→ 导入 → 点与文档恢复。
5. 停 DashScope(改错 key)→ 再粘贴 → 规则建议仍在，托盘标注模型建议缺失。

明确不做：练习/能力、图投影（若在阶段 2 未完成，本阶段必须补上）。

## 阶段 4：学习闭环（PRD 阶段 4)

**目标**：能力 + 练习页 + 分级提示 + 证据 + 调度 + 今日复查 + 失败登记。

任务：

1. 迁移：`capabilities`、`capability_objects`、`evidence`、`review_states`。
2. 练习页：题面/能力原句先行、材料被挡；`tiered_hints` 逐级展开（键盘 1–4)；自评四档 + 障碍原文；`hint_level >= threshold` 拒绝 `independent`(threshold 默认 3，存能力上）；失败后回链到点。
3. `ts-fsrs` 封装与 `review_states` 重放；三种复习触发（到期/核心定义变更标注重看/再次失败提前排入）。
4. 今日页接入真实到期能力；焦点页「能力」投影；能力投影里迁移能力的门槛锁定态。
5. 失败现场建能力：用障碍原文创建能力，用户改句后保存。

测试：

- 纯函数：FSRS 封装固定时钟夹具（一条固定证据序列 → 断言同一 `due_at`)；证据约束（阈值、迁移门槛、saw_material 不推进）。
- 集成：删 `review_states` 整表 → 重放 evidence → `due_at` 一致；被动浏览路由不存在（无任何 GET 产生 evidence)。

浏览器验收（csi):

1. LC140 点 → 能力投影 → 开始做 → 展开到第 3 级提示 →「独立完成」按钮禁用并写明原因 → 选「没做出来」→ 勾一个障碍 → 今日页出现该障碍原文。
2. 今日页「该复查」→ 独立解释 → 自评独立 → 复查日后移（界面显示新日期与原话证据）。
3. 创建迁移能力 → 未通过独立前练习入口锁定并写明原因。

明确不做：交错会话、自动评分、个人 FSRS 权重。

## 阶段 5：投影补齐与学科块（PRD 阶段 5,MVP 收口）

**目标**：放射图投影、学科块第一批、对比矩阵自动生成、核心定义变更的待确认视图。

任务：

1. 图投影：以焦点为中心的放射 SVG（来历左/去向右/对照上/变化下），节点带一句话摘要，点击换焦点，一跳 ≤50。
2. 学科块：`algo_problem`/`theorem`/`lang_pattern` 注册三件套 + 编辑器插入入口 + 粘贴/导出往返。
3. 对比矩阵从已接受 `contrasts` 关系 + 两端点自动生成（无第二份数据）。
4. 核心陈述 `core_version` 增加 → 引用该点的合集标待确认 → 逐处确认（只改该合集已读版本）。

测试：

- 纯函数：图坐标纯函数（四扇区方位、序号布局、>50 截断）；学科块粘贴/导出往返夹具。
- 集成：矩阵单元格确来自关系表（改关系 → 矩阵变）；待确认按合集独立。

浏览器验收（csi):

1. 「状态等价」图投影 → 四方位邻居可见 → 点「决策树」→ 焦点切换、图重排。
2. 数学领域新建点 → 插入定理块与公式块（KaTeX 渲染）→ 保存刷新不丢；英语句型块同理。
3. 改「状态等价」核心陈述 → 两个引用它的合集都标待确认 → 确认一个，另一个仍待确认。
4. 走通原型场景 A–F 全流程（对照 `docs/prototype/index.html` 导览层逐场景点一遍）。

明确不做：两跳以上图探索、交错会话、自动评分。

## 交接给开发 Agent 的注意事项

1. 任何产品语义的疑问，先查 PRD;PRD 与本文冲突时以 PRD 为准并回报冲突。
2. 原型是交互与视觉参照，不是实现代码；不要在产品代码里引用原型文件。
3. `packages/doc-schema` 的粘贴夹具是阶段 0 的既有资产，保持绿；扩展块类型时先加夹具。
4. 密钥只在 `.env`；文档与代码里出现真实密码/key 视为事故。
5. 每阶段完成后更新本文件对应阶段的「完成日期 + 验收结果」一栏，再开下一阶段。
