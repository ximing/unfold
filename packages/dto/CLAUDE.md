# 共享契约指令 (`packages/dto`)

## 这个目录负责什么

- 承载 `@unfold/server` 与 `@unfold/web` 共用的 Zod 4 数据校验 schema 与 TypeScript 推导类型。
- 作为前后端 HTTP 请求体、响应体及图谱核心模型（合集、点、边、九种卡片（含 `rich`）、搜索命中）的唯一契约真相源。

## 放置约束

- **放什么**：
  - `src/graph.ts`：**现行主契约**，包含合集、点、点边、合集边、九种卡片（原八种加富文本 `rich`，`cardContentSchemas`）及搜索接口的全部 Zod schema 与导出类型。
  - `src/api.ts`：登录、注册、账号与统一错误响应契约。
  - `src/rich-doc.ts`：富文本文档节点、属性与读写内容校验；写入 `doc`，响应包含服务端派生的 `plain`。
  - `src/index.ts`：包的公开导出；新增公共 schema 和类型需同步导出。
  - 与 schema 同目录的 `.test.ts` 契约单元测试。
- **不放什么**：
  - 任何依赖 Node.js 原生模块、数据库驱动（Drizzle / `pg`）或浏览器 DOM API 的代码。
  - 仅单端使用的内部状态类型（如前端 `LibraryState` 或服务端数据库行类型）。

## 开发偏好

- **严格对象校验**：所有写操作请求体与卡片 `content` 必须使用 `z.strictObject(...)`，拒绝未知字段。
- **文本校验与中文提示**：
  - 名称、标题、边标签使用 `trim()` 后校验非空与最大长度（标题/名字 1–80 字，边标签 1–40 字，点描述 0–160 字）。
  - 必填项为空时的校验文案必须保持中文且与服务端 `http.ts` 的 `knownMessages` 对齐（如 `'标题不能是空的'`、`'名字不能是空的'`、`'关系说明不能是空的'`）。
- **字段映射约定**：API 契约中卡片类型字段统一命名为 `type`（对应服务端数据库列名 `card_type`）。
- **契约边界**：图谱契约由 `src/graph.ts` 组织并复用 `rich-doc.ts`；点允许同名，名称仍遵循上面的长度与非空校验。`kind: text | image` 区分呈现形式；合集中的坐标与图片宽度不成为点的全局属性。

## 指令文件双向同步

- 同目录的 `AGENTS.md` 与 `CLAUDE.md` 是同一份项目规则，内容必须保持完全一致。
- 后续 Agent 修改任意一方时，必须在同一次变更中同步更新另一方；新增、移动或删除项目级指令文件时也要成对处理。
- 完成前逐对检查内容一致；若已有差异，先核对实际代码与用户要求再合并，不能直接覆盖另一方独有的有效规则。
