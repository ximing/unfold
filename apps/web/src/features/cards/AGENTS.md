# 卡片与富文本编辑

- 本目录放卡片展示、编辑器、空内容构造与元数据。HTTP 状态更新通过 `../library/`，共享数据契约来自 `@unfold/dto`。
- 卡片类型、颜色与标签以 `card-meta.ts` 为前端注册入口，类型集合与 DTO 对齐；点本身不设业务类型色标。
- 创建后不能修改卡片 `type`；`rich` 只挂在点上，原有八种卡片仍可挂在点与边上。
- `rich/` 放 Tiptap 扩展、工具栏、粘贴处理与上传。富文本格式变更须同时核对 `packages/dto/src/rich-doc.ts` 与服务端纯文本派生逻辑。
- 富文本写入提交 `doc`；存储／响应中的 `plain` 由服务端生成，不信任客户端派生值。
- 文稿图片属于卡片，画布图片属于点；图片引用沿用资产 ID，不把图片字节或任意外部地址塞入富文本契约。
- 编辑草稿接入共享保存总线，保持失焦、⌘S 与静默保存协作，避免服务器回声覆盖未提交的新输入。

## 指令文件双向同步

- 同目录的 `AGENTS.md` 与 `CLAUDE.md` 是同一份项目规则，内容必须保持完全一致。
- 后续 Agent 修改任意一方时，必须在同一次变更中同步更新另一方；新增、移动或删除项目级指令文件时也要成对处理。
- 完成前逐对检查内容一致；若已有差异，先核对实际代码与用户要求再合并，不能直接覆盖另一方独有的有效规则。
